# FolderCompareWPF

Windows용 폴더 비교 및 텍스트 편집 도구 (.NET 10 WPF). 기본 빌드는 i-luncher에 통합되는 라이브러리이며, 런처 프로세스에서 바로 창을 엽니다. 별도 EXE가 필요하면 이 프로젝트를 `-p:ILuncherIntegrated=false`로 빌드하세요.

Send / Receive로 소스를 동기화할 때는 상위 i-luncher 폴더의 `Build.ps1 -App folder-compare`로 빌드하고 `Start-Launcher.cmd`로 실행하세요. 아래의 직접 빌드·실행 명령은 [로컬 작업 복사본](../README.md)에서 사용해야 원본 clone에 빌드 폴더가 생기지 않습니다.

기본 윈도우 제목 표시줄 대신 앱 테마에 맞춘 상단 바를 사용합니다. 상단을 드래그해 창을 이동하고, 두 번 클릭해 최대화/복원할 수 있습니다. 오른쪽 버튼으로 최소화·최대화/복원·닫기를 실행합니다. 파일 비교 진행 정보는 왼쪽에 유지됩니다.

- 폴더 아이콘으로 A/B 경로를 선택합니다. **A 폴더 / B 폴더** 버튼은 해당 경로를 탐색기로 엽니다.
- **비교**를 누르면 A에만 있는 파일, B에만 있는 파일, 동일/다른 파일을 분류합니다.
- 목록의 **파일명**을 클릭하면 좌우 비교·편집 화면이 열립니다. **Ctrl+클릭**으로 여러 파일을 추가 선택하거나 선택 해제합니다. Ctrl 없이 클릭하면 해당 파일만 선택됩니다. 선택된 파일들은 파란 배경으로 표시됩니다.
- **Shift+클릭**은 기준 파일부터 클릭한 파일까지 화면에 펼쳐진 파일을 범위 선택합니다. **Ctrl+Shift+클릭**은 기존 선택에 범위를 추가합니다. **Shift+↑/↓, Home/End**도 범위 선택을 지원합니다. 접힌 폴더 안의 파일은 범위에 포함하지 않습니다.
- **선택 파일 A → B 덮어쓰기**를 누르면 선택한 파일 중 A에 있는 파일만 복사합니다. 버튼에 복사 대상 개수가 표시됩니다. 확인창에 표시된 파일만 처리하며, 하위 폴더를 생성하고 기존 B 파일은 덮어씁니다. 완료 후 다시 비교합니다. 바이너리 파일도 복사할 수 있습니다.
- **공백·줄바꿈 무시**를 켜면 텍스트에서 모든 공백·탭·줄바꿈 문자를 제외해 비교합니다. 문자열 내부 공백도 무시하므로 코드의 의미를 판정하는 옵션은 아닙니다. 원본 편집 내용과 저장 형식은 유지됩니다. 옵션 변경 시 다시 비교합니다.
- 텍스트 비교·편집은 기존 제한인 파일당 16MB 이하에 적용됩니다. 더 큰 파일은 바이트 단위로 비교합니다.
- 우측 색상 표시의 왼쪽 절반은 A, 오른쪽 절반은 B입니다. 테두리는 현재 보이는 범위이며, 색상 표시를 클릭하면 해당 행으로 이동합니다. 편집 중에는 오래된 표시를 숨기고 저장 후 갱신합니다.
- 긴 줄은 가로로 스크롤합니다. 파일에 행을 추가하거나 제거해도 양쪽 스크롤은 대응하는 비교 행을 기준으로 동기화합니다.
- 편집 후 A/B 저장 버튼 또는 Ctrl+S로 저장합니다. **저장** 버튼은 비교 보고서를 저장합니다.

아이콘 원본 생성 코드는 `Assets/GenerateIcon.ps1`에 있으며 16~256px ICO를 생성합니다.

## 빌드와 검증

```powershell
dotnet build FolderCompareWPF.csproj -c Release
dotnet run --project DemoData/DemoVerifier/FolderCompareWPF.DemoVerifier.csproj -c Release
```

검증기는 임시 폴더를 사용합니다. 비교·편집·저장, 선택 복사와 덮어쓰기 실패 시 보존, 공백 옵션 전환, 원본 내용 보존, 스크롤 표시와 긴 줄, 점진적 비교, 큰 파일 처리를 검증합니다. 탐색기 실행과 복사 확인 대화상자는 실제 사용 환경에서 수동 확인할 수 있습니다.

## 대량 파일 성능 개선

- 내용 비교를 최대 8개에서 32개 파일 쌍 병렬 처리로 늘렸습니다. 양쪽 모두 256KB 이하인 파일은 동기 읽기로 작업 생성 비용을 줄이고, 그보다 큰 파일은 A/B를 비동기로 동시에 읽습니다. 폴더 검색은 A/B 각각 최대 8개 전용 작업으로 하위 폴더를 나눕니다.
- 전체 검색이 끝날 때까지 기다리지 않습니다. 같은 상대 경로가 양쪽에서 발견되는 즉시 비교 대기열에 넣어 검색과 내용 비교를 겹쳐 진행합니다. 한쪽에만 있는 파일은 검색 완료 후 확정합니다.
- 200개 결과마다 75ms를 기다리던 제한을 제거했습니다. 결과가 준비되어 있으면 8ms 단위로 화면 작업을 나누고 입력 처리에 실행 시간을 양보합니다.
- 파일이 10,000개 이상이면 경량 파일 데이터를 보관하고, 펼친 폴더에서도 현재 화면에 보이는 행만 생성합니다. 한 폴더에 많은 파일이 있으면 목록을 묶어서 연결해 항목별 화면 알림을 줄입니다. Ctrl/Shift 선택 상태는 화면 밖에서도 유지되며, 비교 완료 판정과 보고서는 전체 결과를 사용합니다.
- 작은 파일은 한 번만 열고 읽어 비교합니다. 크기가 같은 파일도 실제 바이트를 비교하며, 기존 인코딩·줄바꿈·공백 옵션 처리를 유지합니다.
- 작은 파일은 읽기 버퍼를 재사용하며, 내용이 다를 때도 별도 바이트 배열로 복사하지 않고 원래 버퍼에서 텍스트를 변환합니다. 검색에서 얻은 크기는 처리 방식 선택에만 사용하고, 열린 파일의 실제 크기와 내용으로 비교합니다. 큰 파일은 1MB 버퍼로 읽고 텍스트 변환을 최대 4개로 제한합니다. 공백·줄바꿈 무시는 공백을 제거한 문자열을 따로 만들지 않고 비교합니다. 진행 정보에 검색 시간과 전체 경과시간이 표시됩니다. 검색·비교가 겹치므로 두 시간을 더하지 않습니다.

이번 환경의 측정 결과는 [성능 검토](DemoData/PERFORMANCE.md)에 기록했습니다. 저장장치, 네트워크 지연, 파일 크기와 파일 수에 따라 전체 시간은 달라집니다.
