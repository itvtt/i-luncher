# Terminal Notes

OpenCode와 일반 셸을 공통 ANSI/VT 엔진과 WebView 없는 네이티브 터미널 화면으로 표시합니다. 독립 실행형 터미널은 `Start-Standalone-Terminal.cmd`로 열 수 있습니다. 플랫폼별 지원 범위·빌드·실행 방법은 [TERMINAL-ENGINE.md](TERMINAL-ENGINE.md)를 참고하세요.

OpenCode용 Windows 작업 공간입니다. OpenCode 작업 서버에 OpenCode 자체 터미널 화면을 연결합니다. 대화·도구 출력·승인·질문은 OpenCode 화면에서 처리하며, TerminalNotes가 별도의 대화 이름이나 말풍선을 덧붙이지 않습니다. 화면은 왼쪽부터 태스크·플랜·터미널 순서이며, 가운데에서 프로젝트 플랜을 편집하거나 요청을 보냅니다. 일반 셸 터미널도 계속 사용할 수 있습니다.

OpenCode 화면의 입력과 세션 메뉴는 OpenCode 자체 기능을 사용합니다. 마우스를 사용하는 화면에서는 Shift를 누른 채 드래그하여 텍스트를 선택합니다. 플랜 전송과 상태 확인은 같은 OpenCode 서버의 API로 연결하며, 전송 확인을 위해 같은 요청을 중복 제출하지 않습니다. 미전송 입력은 앱이 열려 있는 동안 유지됩니다.

OpenCode 터미널 본문 전체의 배경은 실제 상태에 따라 진행 중에는 녹색, 승인·질문·선택 대기에는 주황색, 그 외에는 회색으로 바뀝니다. OpenCode가 출력한 배경색에도 상태색을 적용하며, 글자와 선택 영역은 읽을 수 있는 대비를 유지합니다.

작업창 안에서 Ctrl+Shift+T를 누르거나 터미널 영역의 **+ 터미널** 버튼을 누르면 현재 작업 폴더에서 독립 OpenCode 터미널 하나를 기존 화면 옆에 추가합니다. 태스크나 플랜이 없어도 바로 열리며, 태스크 등록·플랜 연결·자동 요청 전송·자동 진행을 하지 않습니다. 기존 터미널과 태스크 선택·플랜 초안·배치는 유지됩니다. 독립 터미널의 이름 변경과 중단·시작은 해당 터미널에만 적용되며, 추가한 터미널을 모두 닫으면 원래 태스크 배치로 돌아갑니다.

터미널 영역 상단의 버튼 하나가 실행 중에는 **■ 중단**, 종료된 상태에서는 **▶ 시작**으로 바뀝니다. 중단해도 탭과 작성 중인 플랜·입력은 남으며, 시작하면 같은 프로젝트와 위치에서 터미널을 다시 엽니다. 터미널 시작만으로 플랜을 자동 전송하지 않습니다.

상단 메뉴는 오른쪽에 정렬하며 상태 모니터 버튼은 표시하지 않습니다. 분할뷰 버튼은 제목 표시줄의 설정·창 제어 버튼 왼쪽에 작은 간격을 두고 배치합니다. 분할된 터미널은 얇은 테두리로 구분합니다. 태스크 터미널 상단에는 태스크명을, 독립 터미널에는 해당 터미널 이름을 한 줄로 표시하며, 이름을 더블클릭하거나 이름 영역에서 F2를 누르면 그 자리에서 수정할 수 있습니다. Enter 또는 다른 곳 클릭으로 저장하고 Esc로 취소합니다. 태스크명을 변경하면 태스크 목록과 함께 갱신되며 프로젝트 폴더·플랜·실행 중인 세션은 유지됩니다. 터미널 선택은 터미널 영역 상단 왼쪽, 새 터미널은 오른쪽에 배치합니다. 태스크와 플랜은 기존 나란한 배치를 유지하며, 플랜과 터미널 사이 테두리의 세로 중앙 화살표 하나로 함께 접고 펼칩니다. 태스크·아카이브는 둥근 배경 안에 나란히 배치하며, 선택한 탭은 은은한 파란 면과 밝은 글자로 구분합니다. 탭에 마우스를 올리면 배경이 반응하고 키보드 포커스는 별도 테두리로 표시합니다. 탭 아래 카테고리는 폴더 아이콘·이름·개수로 표시합니다.

태스크는 폴더·제목·시작/중단·반복 실행 체크박스를 한 줄로 표시합니다. 현재 상태는 시작·중단 버튼의 아이콘과 툴팁으로 확인합니다. 태스크·아카이브 탭 오른쪽의 `new` 버튼은 새 프로젝트를 바로 만듭니다. 새 카테고리는 카테고리 트리 맨 아래의 **`+새카테고리` 항목**을 눌러 이름을 입력하고 저장하면 생성됩니다. 태스크가 없어도 이 항목은 표시됩니다. 플랜 패널의 자동 진행은 위쪽에 표시하며, 작은 저장·실행 버튼은 **플랜에 추가** 입력창 아래 오른쪽에 표시합니다.

카테고리와 카테고리 안의 태스크는 이름순으로 정렬합니다. 기존 태스크는 **미분류**에 표시하며, 태스크를 원하는 카테고리로 드래그하거나 우클릭의 **카테고리 지정**으로 이동합니다. 실행 상태나 터미널 칸이 바뀌어도 분류는 바뀌지 않습니다. 카테고리 우클릭에서 이름을 바꾸거나 삭제할 수 있고, 삭제하면 포함된 태스크는 미분류로 돌아갑니다. 분류는 작업 폴더별로 저장되며 아카이브 이동·복원에도 유지됩니다. 이 분류 변경은 실제 프로젝트 폴더를 이동하지 않습니다.

터미널 선택 목록은 아직 터미널을 열지 않은 프로젝트도 이름순으로 표시합니다. 처음 실행해도 작업 폴더의 일반 태스크 목록을 실행 기록보다 먼저 표시하며, 아카이브 프로젝트와 태스크들을 담는 기본 작업 폴더 자체는 터미널 선택 목록에서 제외합니다. 폴더 목록을 읽는 도중 클릭하면 로딩 안내 뒤 같은 메뉴에 전체 목록이 채워집니다. 저장된 프로젝트도 함께 포함하며, 상단에서 전체 프로젝트 수와 열린 터미널 수를 따로 확인할 수 있습니다. 열려 있는 프로젝트는 기존 세션으로 이동하며, 미실행 프로젝트를 선택하면 빈 칸에 터미널을 엽니다. 작은 분할에서는 OpenCode 화면 전체가 들어오도록 표시 배율을 자동으로 줄이며, 칸을 넓히면 원래 배율로 돌아옵니다. 빈 터미널 칸의 선택 목록도 태스크·아카이브 탭에 관계없이 일반 태스크만 표시합니다. 메뉴는 터미널 영역 안에서 열리며, 프로젝트가 많으면 스크롤하여 마지막 항목까지 선택할 수 있습니다.

태스크와 터미널에는 별도의 재실행 버튼을 표시하지 않습니다. 다시 시작하려면 **중단**한 뒤 같은 버튼의 **시작**을 누릅니다.

## 실행

`Start-TerminalNotes.cmd`를 실행합니다. 실행기는 `artifacts/win-x64-independent-opencode-terminals/TerminalNotes.exe`를 사용합니다. Windows 10 1809 이상 또는 Windows 11, .NET 10 Desktop Runtime과 OpenCode 구성이 필요합니다. 레거시 화면을 선택할 때에는 WebView2 Runtime이 필요합니다.

창은 현재 모니터의 작업표시줄을 제외한 영역에 맞춰 열립니다. 저장된 크기가 화면보다 크면 자동으로 줄이며, 최대화할 때도 작업표시줄 위에 하단이 표시됩니다.

최초 실행은 OpenCode 확인 → 작업 폴더·Auto Mode 설정 → 프로젝트 선택 순서입니다. 기본 작업 폴더는 `C:\opencode`이며 `--workspace "프로젝트 경로"`도 지원합니다. Auto Mode는 OpenCode의 파일 수정·명령 실행 승인 설정입니다. 설정 변경은 기존 터미널을 재시작하지 않습니다.

앱 재실행은 이미 열린 창을 복원합니다. X/Alt+F4는 트레이로 숨기고 세션을 유지합니다. 완전히 종료하려면 트레이나 세션 메뉴의 **프로그램 종료**를 사용합니다. 완전 종료 후에는 프로젝트를 다시 선택하며 저장한 문서는 보존됩니다. 미전송 초안은 메모리에만 유지됩니다.

## 자동 진행(loop) 진단

태스크를 우클릭하고 **자동 진행 진단 로그 열기**를 선택하면 중단·대기·복구 이유를 확인할 수 있습니다. 기본 로그는 `%LOCALAPPDATA%\TerminalNotes\settings.json.automation-diagnostics.jsonl`이며, 다른 설정 파일로 실행하면 해당 설정 파일 경로 뒤에 `.automation-diagnostics.jsonl`이 붙습니다.

로그에는 발생 시각, 프로젝트, 현재 세션·요청 식별자, 복구 단계, 오류 코드·종류와 마지막 실제 진행 시각을 기록합니다. 상태 변화와 활성 작업의 주기적인 점검을 남기며 요청 본문·플랜 내용은 기록하지 않습니다. 일시적인 점검 예외는 현재 작업을 유지하며 다시 확인하고, 전송 결과가 불확실한 요청은 중복 전송하지 않습니다.

사용자 확인이 필요한 상태는 태스크 상태 설명과 툴팁에 표시하고, 알림이 허용되어 있으면 **Loop 확인 필요** 트레이 알림을 띄웁니다. 알림은 실행을 막지 않으며 알림을 꺼도 로그와 상태 설명은 유지됩니다.

처음 사용하는 경우 왼쪽의 **new**로 작업 폴더를 만듭니다. 빈 터미널 칸을 클릭하면 기존 태스크 목록에서 선택할 수 있습니다. **플랜에 추가**에 원하는 작업을 적고 입력창 아래의 **저장** 또는 **실행**을 누릅니다. 저장만 하면 모델로 전송하지 않습니다.

화면 전체가 **15초 이상 응답하지 않으면** UI 바깥의 감시가 `.ui-diagnostics.jsonl`에 시각, 마지막 터미널 처리 단계와 프로세스 식별자를 기록합니다. 태스크 우클릭 → **화면 멈춤 진단 로그 열기**로 확인합니다. 화면이 다시 응답하면 복구 기록과 상태 안내를 남깁니다. 이 로그는 응답 정지를 관측한 기록이며 원인을 자동으로 확정하거나 앱 전체를 강제 종료하지 않습니다. 터미널 크기 변경과 종료 정리는 각 터미널의 백그라운드 작업에서 처리하여 Windows의 응답 대기가 공통 UI를 직접 막지 않도록 했습니다.

## 전역 지침과 프로젝트 플랜

제목 표시줄의 **작업 설정(톱니바퀴) → 전역 에이전트 지침 → 편집**에서 공통 Markdown을 수정·추가·저장합니다. 기본 경로는 `%LOCALAPPDATA%\TerminalNotes\Instructions\global-agent-instructions.md`입니다. 일반 Markdown 편집기로 수정해도 됩니다.

직접 수정한 지침을 유지하며, 교체가 승인된 이전 지침과 내용이 같은 파일은 원본 백업 후 갱신합니다. 기본 지침 원문은 `global-agent-instructions.md`에서 확인할 수 있습니다. 편집 이후 외부에서 내용이 바뀌면 저장을 거부하고 초안을 유지합니다. 새 터미널/CMD 실행부터 공통 파일 경로가 연결되고, 연결된 세션은 다음 모델 요청에서 파일을 읽습니다. 사용자 OpenCode 설정이나 프로젝트 AGENTS.md는 수정하지 않습니다.

새 프로젝트의 기본 플랜은 **목표 (필수)**와 **요구사항·제약 사항·완료 기준·참고 자료 (권장)**로 구분합니다. 기존에 작성한 플랜은 자동으로 바꾸지 않습니다.

프로젝트별 기준 문서는 기존과 같은 `<프로젝트>/terminal-notes/plan.md`입니다. 프로젝트를 선택하면 해당 파일을 읽고, 문서 전체를 직접 편집할 수 있습니다. **저장**은 문서와 추가 입력을 저장하고, **실행**은 저장 후 같은 프로젝트의 터미널로 요청을 보냅니다. 추가 입력이 없으면 저장한 플랜 전체를 실행합니다. 외부 수정과 충돌하면 초안을 덮어쓰지 않습니다.

## 플랜 입력

가운데 플랜 문서 아래 **플랜에 추가** 입력창에서 요청을 작성합니다. 입력창 아래 오른쪽의 **저장·실행** 버튼을 문서와 함께 사용하며, 별도의 전송 버튼은 표시하지 않습니다. Ctrl+S는 저장, Ctrl+Enter는 실행입니다. 질문은 OpenCode 터미널에 직접 입력합니다. 위쪽 플랜 문서 편집 영역은 계속 표시되고 입력 초안은 프로젝트별로 유지됩니다.

**저장**은 기존 플랜 뒤에 입력한 원문만 추가하고 전송하지 않습니다. **실행**은 저장한 추가 요청을 같은 프로젝트의 터미널에 전달합니다. 시각이나 추가 요청 제목은 자동으로 넣지 않습니다. 저장에 실패하면 전송하지 않습니다. 전송에 실패해도 저장된 플랜과 입력 초안은 남으며, 반복 저장이나 같은 요청 재시도는 플랜에 중복 추가하지 않습니다.

기존의 모든 터미널 입력 수집 플러그인은 새 실행과 CMD에 추가하지 않습니다. 과거 `terminal-inputs.md`와 실행 기록은 삭제하지 않습니다. 터미널에 직접 입력한 내용은 플랜에 자동 복사되지 않습니다. OpenCode 자체 세션 기록과 사용자가 별도로 설정한 기록 기능은 OpenCode 설정을 따릅니다.

## 싱글 터미널과 분할

지휘·검토·구현 역할 팀 대신 프로젝트마다 하나의 터미널을 재사용합니다. 과거 멀티 설정으로 역할 팀을 다시 생성하지 않으며, 예전 Running/Scheduled 역할 실행은 중단 상태로 보존합니다. 과거 기록 때문에 모델 작업을 자동 재개하지 않습니다.

상단 **1/2/3/4/6/8 분할**로 고정된 터미널 칸 수를 선택합니다. 왼쪽 태스크 목록은 오른쪽 테두리 중앙의 화살표 버튼으로 접고 펼칩니다. 접으면 터미널 영역이 넓어지고, 다시 펼치면 조절했던 목록 폭으로 돌아옵니다. 접힘 상태와 폭은 재실행 후에도 유지됩니다. 카드는 **프로젝트 폴더 아이콘**, 이름, **시작/중단 버튼 하나**, **Loop 체크박스 하나**를 한 줄로 표시합니다. 폴더 아이콘을 누르면 해당 카드의 프로젝트 폴더가 탐색기에서 열립니다. 버튼은 대기 중에는 ▶ 시작, 실행·준비 중에는 ■ 중단으로 바뀝니다. 터미널 열기 버튼은 제거했습니다. 태스크 카드를 원하는 터미널 칸으로 **드래그 앤 드롭**합니다. 각 터미널 칸은 편집 가능한 태스크명 한 줄과 터미널 본문을 표시합니다. 빈 칸의 **태스크 선택**을 클릭하면 태스크 목록만 표시합니다. 이 메뉴에는 새 프로젝트 만들기와 프로젝트 폴더 열기를 표시하지 않습니다. 취소하면 기존 배치를 유지합니다. 새 프로젝트를 추가하거나 폴더를 불러올 때 기존 터미널 배치를 유지하며, 비어 있는 가시 칸에만 자동 배치합니다. 칸이 모두 사용 중이면 태스크와 플랜만 추가·선택하고 원하는 칸으로 직접 드래그할 수 있습니다. 이미 숨겨진 칸에 배치된 프로젝트는 그 위치를 유지합니다. 위치 이동과 글자 선택은 마우스 해제·포커스 상실 시 드래그 상태를 정리하며, 복사할 선택 영역은 유지합니다.

이미 배치된 태스크 카드를 다른 칸에 놓으면 두 자리를 바꿉니다. 배치되지 않은 태스크를 채워진 칸에 놓으면 그 칸만 교체하며 기존 세션은 계속 유지합니다. 태스크 우클릭의 **터미널 칸 비우기**는 배치만 해제하고 작업은 종료하지 않습니다. 작업 중단은 태스크의 ■ 또는 터미널 선택 메뉴에서 해당 세션을 우클릭해 선택합니다. 세션 종료도 터미널 메뉴에서 선택합니다. 분할 수를 줄여도 숨겨진 칸의 배치·세션·출력·초안이 유지되며 다시 늘리면 돌아옵니다. 가운데 플랜 패널은 선택한 프로젝트를 따릅니다.

태스크의 **시작**은 플랜이 없거나 비어 있어도 OpenCode 터미널을 엽니다. 이때 자동 요청을 보내지 않으며 터미널에 바로 입력할 수 있습니다. 플랜 영역에는 **플랜 없음 · 작업 시작 대기**를 표시해 OpenCode를 연 상태와 플랜 작업의 시작 여부를 안내합니다. 저장된 플랜에 내용이 있으면 같은 터미널로 플랜 실행 요청을 보냅니다. 플랜 요청은 화면 입력창의 로딩 시점에 의존하지 않고 해당 OpenCode 세션에 전달하며, 정확한 메시지의 접수를 조회해서 확인합니다. 연결 실패는 자동 재시도하고, 입력을 보내기 전에 터미널이 종료되거나 준비가 5분 이상 응답하지 않으면 해당 앱 소유 터미널을 자동 재시작합니다. 20초 이상 걸리는 단계는 경과 시간을 표시합니다. 응답이나 상태 알림을 놓친 경우 같은 메시지를 자동 재조회하며, 전송 결과가 불명확한 요청은 중복 제출하지 않습니다. 사용자의 중단·입력·승인 대기와 플랜 변경을 존중합니다. 플랜 없이 터미널을 열어도 플랜 원문을 바꾸거나 Loop 작업을 자동으로 시작하지 않습니다.
터미널 선택 메뉴에서 세션을 우클릭해 고르는 **저장된 plan.md 다시 읽기**는 해당 프로젝트의 저장된 `terminal-notes/plan.md`를 디스크에서 다시 읽어 실행합니다. 실행 중인 작업은 먼저 중단하고 같은 프로젝트 터미널을 재사용합니다. 편집 중인 미저장 플랜은 보존하며, 저장된 플랜이 없거나 비어 있으면 OpenCode 터미널만 열어 입력을 기다립니다.

태스크 상태에는 작업 상태와 OpenCode 상태 확인 여부를 함께 표시합니다. 실제 연결·상태 요청 중에는 **확인 중**, 연결된 상태에서 다음 응답을 지켜볼 때는 **상태 감시 중**, 연결이 끊겨 재시도를 기다릴 때는 **재연결 대기**, 확인 기능이 실행되지 않을 때는 **확인 안 함**으로 구분합니다. 상태 감시는 작업 진척이나 완료 검증을 뜻하지 않습니다. 승인·입력 대기와 오류도 카드에 표시합니다.

태스크/아카이브 목록과 프로젝트 제목 변경을 유지합니다. 우클릭으로 프로젝트 폴더 전체를 보관·복원하며, 실행·승인 대기는 먼저 중단해야 합니다. 코드·플랜·기록을 함께 이동하고 같은 이름의 폴더를 덮어쓰지 않습니다. 가운데 플랜과 오른쪽 터미널의 기본 폭은 3:7이며 구분선으로 조절합니다. 플랜 오른쪽 테두리 중앙의 화살표로 플랜을 접고 펼치며, 다시 펼치면 조절한 폭으로 돌아옵니다. 접힌 상태에도 경계의 펼치기 버튼은 남습니다.

## Loop

각 프로젝트 카드의 **Loop 체크박스**로 켜고 끕니다. 설정은 해당 프로젝트에만 적용되며 별도 설정 버튼은 없습니다. 종료 시간이 필요하면 **카드 우클릭 → Loop 종료 예약**에서 설정합니다. 예약 시각은 체크박스 툴팁과 우클릭 메뉴에 표시합니다. OpenCode에 설정된 기본 모델을 그대로 사용합니다. 에이전트에게 최신 플랜과 현재 코드를 대조하고 구체적인 남은 작업 한 가지를 구현·검증하도록 요청합니다. 요구사항별로 현재 코드·변경분·유효한 검증 결과부터 확인합니다. 이미 반영된 항목은 근거와 todo 상태만 정리하고 다시 구현하지 않도록 지시합니다. plan.md나 todo의 미완료 표시만으로 재작성하지 않으며, 실제 누락·결함만 최소 수정하고 모두 충족되면 코드 변경 없이 마칩니다.

진행은 native 세션·작업 목록·도구 근거로 확인합니다. 답변이 길어지거나 busy 상태가 유지되는 것만으로 계속 진행했다고 보지 않습니다. 토큰 절약을 위한 재요청 횟수 제한을 두지 않습니다. 자동 진행/Loop이 켜진 미완료 요청은 1분·3분·이후 최대 10분의 대기 간격을 두고 계속 재개합니다. 처리할 일이 완료되면 멈추고, 추가 목표는 플랜 입력으로 누적합니다. 자동화 장치만으로 생성 코드의 품질을 보장하지 않으며 실제 모델 검증은 별도로 필요합니다.

자동 진행 또는 Loop이 켜진 현재 요청에서, 로딩 표시만 계속되고 응답·추론·도구 내용에 **5분간 변화가 없으면 정체 의심**으로 표시합니다. 같은 상태가 **15분간 유지되면 해당 요청을 취소**하고, 실제 idle 확인 후 최신 플랜을 기준으로 재요청합니다. 모델이 todo를 만들기 전에 멈춘 경우도 정확한 현재 사용자 요청을 확인한 뒤 복구합니다. 응답 내용 변화는 정체 시간을 초기화하지만, 실제 작업 진전 없는 재요청의 대기 간격은 초기화하지 않습니다. 긴 작업으로 최근 50개 메시지에 원래 요청이 빠지면, 응답들이 가리키는 동일한 요청 ID를 검증해 원문을 다시 조회합니다.

반복 실행 중 프로젝트 안의 앱 실행 명령 하나가 진행 없이 남아 있는 경우도 감지합니다. 지원하는 실행 명령과 현재 요청·도구가 정확히 일치하고 승인·질문·하위 작업이 없을 때, **15분 정체 후 해당 OpenCode 요청에 취소를 요청**합니다. 취소 접수만으로 실행한 프로그램의 종료를 단정하지 않으며, 새로운 idle 상태를 확인한 뒤 후속 요청을 보냅니다. 일반 빌드·테스트·임의 스크립트를 일괄 종료하지 않습니다. 새 실행 요청에는 미리보기 실행 시간을 제한하고 이번에 만든 프로세스를 정리하도록 안내합니다.

취소를 요청했는데도 **2분 더 동일한 busy 상태**이고 실행 중인 도구·하위 작업·승인 대기가 없으면, 해당 터미널의 앱 소유 프로세스 종료를 확인한 뒤 새 터미널에서 저장된 plan.md와 원래 요청으로 이어갑니다. 현재 파일을 먼저 확인해 이미 적용한 작업을 반복하지 않도록 지시합니다. 프로세스 재시작 횟수에도 제한을 두지 않습니다. 새 터미널이 다시 정체되면 같은 15분 정체·취소 후 2분 확인 절차를 거쳐 복구합니다. 원래 요청 전체를 보존하고 이전 복구 안내문을 반복 누적하지 않습니다. 재시작 자체가 실패하거나 전송 여부를 확인할 수 없으면 확인 필요 상태를 남깁니다. 기존 프로젝트 파일과 OpenCode 대화 기록은 삭제하지 않습니다. 사용자가 중단하거나 요청·플랜을 바꾸면 진행 중인 복구를 취소합니다.

승인·질문, 사용자 입력, 중단, 연결 오류와 전송 결과 불명확 상태를 보호합니다. 일반 셸에 자연어 요청을 보내지 않고, OpenCode의 입력 가능한 세션인지 확인합니다. 종료 예약과 해제 뒤에는 새 개선을 시작하지 않습니다. 앱을 다시 열었다는 이유만으로 이전 작업을 재전송하지 않습니다.

Loop 실행 중에는 Windows에 **시스템·디스플레이 사용 중 요청**을 유지해 화면보호기의 자동 실행·화면 꺼짐·자동 절전을 보류합니다. 최소화하거나 트레이로 숨겨도 요청은 유지하며, 중단·완료·Loop 해제·앱 종료 시 해제합니다. 화면보호기 활성값·시간·Windows 전원 계획·시스템 정책·레지스트리는 변경하지 않고 가짜 입력도 보내지 않습니다. 절전에서 복귀하면 전원 요청을 다시 등록합니다.

`PowerSetRequest`의 `DisplayRequired`와 `SystemRequired` 요청을 사용합니다. [Microsoft의 전원 요청 설명](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_power_request_type)에 따른 동작이며, 별도 보안 정책이나 사용자의 잠금·절전 명령을 해제하는 기능은 아닙니다.

## CMD 이어가기와 상태 모니터

태스크 우클릭 또는 터미널 선택 목록의 해당 세션 우클릭에서 **CMD에서 이어가기**를 고르면 확인된 같은 OpenCode 세션을 독립 CMD 창으로 넘깁니다. 플랜 초안을 저장하고 앱 소유 프로세스 종료를 확인한 뒤 이어갑니다. 외부 CMD가 실행 중인 프로젝트의 앱 재실행·아카이브 이동은 차단하며, 앱 종료가 외부 CMD를 종료하지 않습니다. 외부 OpenCode의 로컬 API에서 원래 세션 ID와 프로젝트를 확인하고 해당 세션의 실행 잠금이 유지될 때만 연결 성공으로 표시합니다. 시작 실패 또는 시간 초과 시 이번 시도의 실행 프로세스만 정리하며, 종료한 앱 터미널의 검증된 세션 ID는 보존합니다. 실패 표시 후 같은 CMD 메뉴로 대화를 다시 열 수 있습니다.

**상태 모니터**는 항상 위의 타일 화면을 열고 기존 터미널을 클릭해 조작합니다. 같은 터미널 화면과 세션, ANSI/TUI·한글·Ctrl+C·터미널 컨텍스트 메뉴를 유지합니다. 녹색은 진행, 주황색은 승인·질문 대기, 회색은 유휴·중단·정체 복구·확인 불가입니다. 미완료 작업이 남아 있다는 이유만으로 카드를 녹색으로 표시하지 않으며, 종료한 프로세스의 이전 busy 상태도 표시하지 않습니다. 응답 종료와 작업 검증 완료를 구분합니다.

## OpenCode 자동 설치

설치 검사에서는 `.exe`의 Windows 실행 형식을 먼저 확인합니다. npm의 설치 미완료 안내문이 `opencode.exe` 이름으로 남아 있으면 이를 호출하는 CMD/PowerShell 스크립트를 실행하지 않습니다. 이미 설치된 Windows용 본체의 패키지 이름·버전과 `--version` 결과를 확인해 사용하며 사용자 npm 파일은 변경하지 않습니다.

`opencode --version` 확인에 실패하면 동의 후 루트 `auto-install.cs`의 `AutoInstall.RunAsync`를 호출합니다. 설치 코드 연결 지점이며 기본 배포에는 별도 다운로드·설치 명령이 없습니다. 실행 결과를 다시 확인하고 설치 성공을 확인한 경우에만 터미널을 엽니다.

UI 테스트는 실제 사용자 폴더/세션 대신 임시 프로젝트와 설정을 사용합니다. `$env:TERMINALNOTES_UI_INDEPENDENT_ONLY='1'`은 실제 네이티브 OpenCode에서 플랜 없는 시작·자동 요청 없음·기존 태스크 보존·중단/시작 및 세션 복원·아카이브/CMD 분리를 검사합니다. 모델 요청은 보내지 않습니다. `$env:TERMINALNOTES_UI_NATIVE_ADD_ONLY='1'`은 기본 네이티브 화면에서 터미널 추가·선택·닫기 후 기존 화면과 실행 상태·출력이 보존되는지 검사합니다. `$env:TERMINALNOTES_UI_COMPOSER_ONLY='1'`을 설정하면 모델을 호출하지 않고 임시 창에서 플랜 입력창·초안·고정 슬롯의 배정/교환/보존을 검증합니다. 포커스를 검사하므로 다른 WPF UI 테스트와 동시에 실행하지 않습니다. 이 UI 테스트 실행기는 마우스·키보드를 검사하며, 테스트 환경의 WPF 종료 시 펜 장치 조회 대기를 피하도록 stylus/touch 지원을 끕니다. 펜·터치 입력은 검증 범위에 포함되지 않습니다. `InputJournal`은 질문 비저장·전역 지침 병합과 저장 충돌을, `AutoResumeController`/`OpenCodeRecovery`/`PlanDispatch`/`StartupDispatch`는 로컬 테스트 서버와 이벤트로 자동 진행·시작 재시도·중복 전송 방지를 검증합니다. `SleepPrevention`은 모의 전원 요청의 수명주기와 실제 Windows 요청의 등록·해제 전후 화면보호기 활성값·대기 시간 보존을 검증합니다. 실제 화면보호기 실행을 기다리는 테스트는 아닙니다. 모의 테스트 통과를 실제 모델이나 보안 정책의 실제 동작 검증으로 간주하지 않습니다.

터미널 분리 검사는 `TERMINALNOTES_UI_INPUT_ONLY=1`로 실행합니다. 임시 PowerShell 터미널 두 개에서 한쪽 크기 변경을 의도적으로 지연시킨 동안 다른 쪽 명령 실행과 원래 프로세스 종료를 확인합니다. `TERMINALNOTES_UI_EXIT_ONLY=1`은 15초 종료 준비 시간 초과 뒤 입력·작업 기록이 유지되는지 검사합니다. `tests/Terminal`은 네이티브 작업 분리와 종료를, `tests/UiResponsiveness`는 UI가 막힌 동안의 로그와 복구·오류 기록을 검증합니다. UI 모드 환경 변수는 하나만 설정하고 순서대로 실행합니다.

화면 미리보기는 위 `COMPOSER_ONLY` 모드에 `TERMINALNOTES_UI_DESIGN_PREVIEW`를 절대 PNG 경로로 지정합니다. 임시 프로젝트와 정적인 터미널 예시로 화면만 캡처하며 모델을 실행하거나 일반 smoke 검사를 대신하지 않습니다. `TERMINALNOTES_UI_DESIGN_WIDTH`(기본 1480, 최소 820), `TERMINALNOTES_UI_DESIGN_LAYOUT`(1/2/3/4/6/8, 기본 2)로 좁은 창과 분할 화면을 확인할 수 있습니다. 일반 검사를 실행할 때는 미리보기 환경 변수를 해제합니다.

과거 `Automation*`의 3역할 실행 테스트는 이전 구현의 자료입니다. 현재 앱의 사용자 경로에서는 역할 자동화가 비활성화되어 있습니다. 실제 모델을 호출하는 테스트는 별도 명시적 요청이 있을 때만 실행합니다.
## 작업 알림

검증된 작업 완료, 명확한 실행 오류, 지속적으로 확인된 장시간 정체에 Windows 알림을 표시합니다. 단순한 터미널 무출력이나 잠깐의 대기, 승인·질문·입력 대기는 알리지 않습니다. 같은 실행의 같은 상태는 한 번만 알리고, 알림을 표시하기 직전에도 해당 작업 상태를 다시 확인합니다.

창의 메뉴 또는 트레이 아이콘 우클릭 메뉴에서 **작업 알림**을 선택하면 알림 사용·영구 끄기와 **5·10·30·60분**, **사용자 지정 시간(분)** 동안 알림 중지를 설정할 수 있습니다. 중지 시간이 끝나면 자동으로 다시 켜지고, 설정은 재시작 후에도 유지됩니다. 중지 중 끝난 작업의 완료 알림을 나중에 몰아서 표시하지 않습니다.
