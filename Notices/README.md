# 런처 공지 게시

[GitHub에서 공지.txt 수정하기](https://github.com/itvtt/i-luncher/edit/main/%EA%B3%B5%EC%A7%80.txt)를 열어 수정합니다. 각 공지의 **첫 줄은 제목**, **다음 줄부터는 본문**입니다. 공지 사이는 `---`만 있는 줄로 구분합니다.

```text
[샘플] 첫 번째 공지
첫 번째 공지의 본문입니다.
본문은 여러 줄로 작성할 수 있습니다.

---

[샘플] 두 번째 공지
두 번째 공지의 본문입니다.
```

**Commit changes…**에서 **main에 직접 커밋**을 선택해 저장하면 자동 게시됩니다. 날짜와 공지 버전은 자동으로 정해집니다. 런처 앱을 다시 빌드할 필요는 없습니다. 게시 상태는 [Publish launcher notices](https://github.com/itvtt/i-luncher/actions/workflows/publish-notices.yml)에서 확인할 수 있습니다.

- **추가:** 마지막에 `---` 구분 줄과 새 제목·본문을 붙입니다.
- **수정:** 제목을 유지하고 본문을 수정하면 읽은 사용자에게도 다시 알립니다. 제목을 바꾸면 새 공지가 됩니다. 같은 제목을 두 번 쓰면 게시되지 않습니다. 대소문자나 공백만 다르게 쓴 제목도 중복으로 봅니다.
- **삭제:** 해당 공지의 제목·본문 블록과 불필요한 구분 줄을 지웁니다. 파일을 모두 비우면 TXT 공지가 모두 내려갑니다. 기존 JSON 공지는 유지됩니다.
- 제목은 120자, 본문은 12,000자 이내로 작성합니다. 제목과 본문은 모두 필요하며, `---`만 있는 줄은 본문에 쓸 수 없습니다.
- TXT 공지는 읽기 전까지 앱 목록 위에 표시됩니다. 본문을 열면 읽음 처리되며, 읽은 공지도 **공지** 버튼에서 다시 볼 수 있습니다.
- 런처를 열 때와 실행 중 30분마다 확인합니다. 런처나 공지 창의 **새로고침**으로 바로 확인할 수 있으며, GitHub Pages 캐시 때문에 반영이 잠시 늦을 수 있습니다. 공지 기능이 없는 기존 런처는 한 번 업데이트해야 합니다.

기존 `Notices/notices.json` 형식도 지원하며, JSON 공지와 TXT 공지를 합쳐 게시합니다. TXT 공지의 제목으로 ID를 정하고, 각 공지의 변경 이력으로 날짜와 버전을 정합니다. JSON의 같은 ID를 수정해 다시 알리려면 `revision`을 올립니다. 모든 공지를 합쳐 최대 100개, 공개 JSON은 256 KiB 이내여야 합니다.

소스 저장소는 비공개로 유지하며 검증한 JSON만 공지 전용 공개 저장소에 게시합니다. 공개 주소는 https://itvtt.github.io/i-luncher-notices/notices.json 입니다. 연결에는 `NOTICE_PUBLISH_KEY` Actions 시크릿과 공개 저장소의 GitHub Actions Pages 설정을 사용하며, 평소 공지를 수정할 때 바꿀 필요는 없습니다. 공지 전용 변경은 Windows 배포 빌드를 실행하지 않습니다.

로컬 검증: `python Tools/CI/Publish-Notices.py Notices/notices.json --text 공지.txt`
