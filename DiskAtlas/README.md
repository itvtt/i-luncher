# DiskAtlas

Windows용 C# WPF 디스크 분석·파일 검색 도구입니다. 기본 빌드는 [통합 i-luncher](../README.md)에 포함되는 라이브러리입니다. 런처에서 실행하면 같은 `i-luncher.exe --app disk-atlas`가 관리자 권한으로 열립니다. 아래 실행 도우미·예약 작업 설명은 별도 EXE를 만드는 독립 배포 방식에만 해당합니다.

Send / Receive로 소스를 동기화할 때는 상위 i-luncher 폴더의 `Build.ps1 -App disk-atlas`로 빌드하고 `Start-Launcher.cmd`로 실행하세요. 아래의 직접 빌드·실행 명령은 [로컬 작업 복사본](../README.md)에서 사용해야 원본 clone에 빌드 폴더가 생기지 않습니다. 관리자 설치 및 앱 데이터 위치는 그대로 유지됩니다.

## 사용

드라이브를 선택하거나 폴더 경로를 입력하고 **분석**을 시작합니다. 용량순 폴더 트리, 큰 파일 목록, 확장자별 집계와 공간 지도로 어떤 파일이 공간을 사용하는지 살펴볼 수 있습니다. 폴더를 선택해 하위 내용을 탐색하고 탐색기에서 해당 위치를 열 수 있습니다.

큰 파일 목록은 상위 10,000개, 검색 결과는 최대 10,000개를 표시합니다. 공간 지도는 폴더 안에 하위 파일을 그리며 한 번에 최대 1,500개 영역을 사용합니다. 전체 파일의 용량 집계는 이 표시 제한과 무관합니다.

상단에서 **논리 크기 기준 / 할당 크기 기준**을 전환하면 폴더 순서, 큰 파일 목록, 확장자 집계와 지도 면적을 다시 계산합니다. MFT 결과는 할당 크기, 추정치인 폴더 스캔 결과는 논리 크기를 기본으로 사용합니다. 생략된 작은 항목의 면적은 빈 영역으로 유지해 표시된 파일이 실제보다 커 보이지 않게 합니다. 폴더 트리는 계층 보호를 위해 크기순으로 고정하고, 큰 파일·검색 표는 크기 열을 실제 바이트 수로 정렬합니다.

상단에 항상 표시되는 **파일 검색** 창에서 파일 이름·파일 내용·이름 또는 내용을 선택하고 검색 버튼이나 Enter를 누릅니다. 사전 분석 없이도 선택한 드라이브/폴더의 파일 목록을 준비한 뒤 검색합니다. 경로를 바꾸면 새 위치를 분석해서 검색하며, 결과는 **검색 결과** 탭에 표시합니다. **파일명과 내용 검색 모두 시스템 파일을 제외**합니다. 디스크 분석은 시스템 파일이 차지하는 공간도 표시합니다. 내용 검색은 실제 파일을 읽으므로 파일명 검색보다 오래 걸릴 수 있으며 취소할 수 있습니다.

검색어에 `AND`, `OR`를 사용해 조건을 조합합니다. 연산자는 대소문자를 구분하지 않으며 **AND가 OR보다 먼저** 적용됩니다. 괄호로 순서를 지정할 수 있습니다.

- `코드 AND 분석`: 두 단어를 모두 포함한 파일 (서로 다른 줄에 있어도 일치)
- `코드 OR 분석`: 둘 중 하나 이상 포함한 파일
- `(코드 OR 설계) AND 분석`: 코드 또는 설계가 있고, 분석도 있는 파일
- `"코드 분석"`: 공백을 포함한 문구 그대로 검색
- `"AND"`: 연산자가 아닌 AND라는 글자 검색

연산자 없는 `코드 분석`도 기존처럼 문구 그대로 검색합니다. ‘이름 또는 내용’ 모드에서는 파일 이름과 내용에 나뉘어 있는 조건도 함께 판단합니다. 내용 검색은 조건마다 파일을 다시 읽지 않고 한 번의 스트리밍 읽기에서 판정합니다. 잘못된 조건식은 디스크 분석을 시작하기 전에 검색 영역에 안내합니다.

검색 제외 대상은 `System` 속성 파일과 그 하위 파일, Windows·Program Files·ProgramData·복구/부팅·휴지통 같은 시스템 경로, 재분석 지점과 오프라인/클라우드 회수 대상입니다. `내 문서/Windows`처럼 사용자가 만든 이름만 같은 폴더는 제외하지 않습니다.

**중복 파일** 탭에서 분석한 위치의 중복 검색을 시작할 수 있습니다. 같은 크기의 후보를 추린 뒤 SHA-256으로 내용을 비교하므로 이름이 달라도 내용이 같은 파일을 찾습니다. 검색 진행 상황을 표시하며 취소할 수 있습니다. 결과에는 중복 그룹, 파일 이름, 크기와 경로가 표시됩니다. 이 탭에서는 넓은 목록을 사용하고 다른 탭으로 돌아가면 지도와 유형 표가 복원됩니다. 행을 선택해 **폴더 열기**를 누르거나 행을 두 번 클릭하면 해당 폴더를 엽니다.

삭제할 파일의 체크박스를 직접 선택한 뒤 **선택 파일 휴지통으로**를 누릅니다. 선택한 개수와 용량을 확인한 후 실행하며, 같은 중복 그룹에서 최소 한 파일은 남겨야 합니다. 삭제 직전에 파일 내용과 파일 식별 정보를 다시 확인하므로 검색 후 변경되거나 교체된 파일은 건너뜁니다. 휴지통 처리가 불가능한 위치는 삭제하지 않습니다.

중복 검색과 삭제에서도 시스템 파일·보호 폴더·연결 파일·오프라인 파일을 제외합니다. 공간 회수에 의미가 없는 빈 파일, 여러 경로가 같은 파일을 가리키는 하드 링크, 별도 데이터 스트림이 있는 파일도 제외합니다. 회수 가능 용량은 파일의 논리 크기를 기준으로 한 예상치이며 휴지통으로 옮기는 즉시 실제 여유 공간이 늘어나는 것은 아닙니다.

내용 검색은 텍스트·코드·로그, 텍스트로 판별된 기타 확장자와 DOCX/XLSX/PPTX의 XML 텍스트를 지원합니다. UTF-8 및 BOM이 있는 UTF-16/UTF-32를 판별합니다. **PDF, 구형 DOC/XLS/PPT, 이미지 OCR과 CP949 자동 판별은 지원하지 않습니다.** Office 문서는 XML 압축 해제 합계 256MiB 또는 ZIP 항목 20,000개를 넘으면 건너뜁니다. 일반 텍스트는 고정 크기 버퍼로 읽으며 작은 용량 제한으로 잘라 검색하지 않습니다.

최초 실행 때 한 번 Windows 관리자 승인(UAC)을 받아 보호된 설치 폴더에 앱을 설치하고 현재 계정용 실행 작업을 등록합니다. 이후 런처 아이콘이나 `dist/win-x64/DiskAtlas.exe`로 실행하면 등록된 작업을 통해 관리자 권한으로 열립니다. 앱을 새로 게시해 내용이 바뀌면 다음 실행 때 업데이트 승인이 필요합니다. Windows 전체 UAC 설정은 변경하지 않습니다.

전체 로컬 NTFS 드라이브에서 MFT 고속 경로를 시도하며, 지원 조건이 맞지 않으면 병렬 폴더 스캔으로 전환합니다. 읽지 못한 항목이나 연결 폴더의 생략 안내, 분석 상세 버튼은 화면에 표시하지 않습니다. 실제 사용 엔진은 요약 카드에서 확인할 수 있습니다. 중복 파일 탭은 선택한 파일을 휴지통으로 보내고, **저장소 최적화** 탭은 검사 후 명시적으로 선택한 임시폴더 파일을 영구 삭제합니다.

### 저장소 최적화

**저장소 최적화** 탭은 자동으로 검사하거나 정리하지 않습니다. **정리 대상 검사**를 눌러야 지정 위치를 살펴보고, 검사가 완료되면 삭제 가능한 파일의 이름·경로·크기·수정 날짜만 목록에 표시합니다. 시스템 파일과 사용 중·읽기 전용 등 삭제 불가 항목은 목록에서 제외합니다. 취소된 검사의 부분 결과나 삭제 완료·실패 항목도 파일 목록에 표시하지 않으며 처리 결과는 요약으로 확인합니다. 검사 결과는 처음에 모두 선택 해제되어 있습니다. 개별 후보를 고르거나 **전체 선택**으로 현재 정리 가능한 후보만 선택할 수 있습니다.

기본 대상은 현재 사용자 `Temp`와 Windows `Temp`의 일반 파일이며, **임시폴더 하위 폴더 포함** 옵션이 기본으로 켜져 있어 일반 하위 폴더도 재귀적으로 검사합니다. 이 옵션을 끄면 지정 임시폴더 바로 아래의 파일만 검사합니다. 파일 이름·확장자·나이에 따른 기본 제한은 없습니다. `System` 또는 숨김 속성 파일과 `.sys`, `.dll`, `.drv`, `.ocx`, `.cpl`, `.efi` 확장자 파일은 목록에서 제외합니다. 재분석 지점 및 오프라인 폴더는 제외하고 폴더 자체는 삭제하지 않습니다. 읽기 전용 파일은 목록에서 제외합니다. 목록에는 수정 날짜와 파일 경로·이름을 표시하므로, 사용자가 내용을 확인해 삭제할 파일을 직접 선택할 수 있습니다. 30일 지난 크래시 덤프와 Windows 오류 보고서의 보관본(`ReportArchive`)은 각각 선택 옵션이며 기본값은 꺼짐입니다.

Downloads, `bin` 폴더, 브라우저 데이터, 사용자 프로필 전반, 임의의 앱·레지스트리는 검색하거나 정리하지 않습니다. 지정 임시폴더 안의 일반 파일도 앱에서 사용 중이거나 재분석 지점·하드 링크·대체 데이터 스트림이 있으면 건너뜁니다. 삭제 직전에 검사 때 확인한 파일 식별 정보와 시각을 다시 대조하고, 바뀐 파일은 삭제하지 않습니다. 임시폴더에 있는 파일이 나중에 필요하지 않다고 보장할 수는 없으므로 목록과 수정 날짜를 확인한 뒤 필요한 파일은 선택에서 제외하세요.

선택 삭제와 정리 가능 파일 전체 삭제는 실행 전 파일 수와 총 용량을 확인합니다. 확인 후 파일은 휴지통을 거치지 않고 영구 삭제됩니다. 작업 중 **취소**하면 이후 항목 처리를 중단하며 이미 삭제된 파일은 복구되지 않습니다. 삭제 후에는 결과 요약을 표시하며, 추가로 삭제하려면 다시 검사합니다.

이 화면은 검사 결과를 먼저 보여주고 항목별 선택·제외를 허용하는 방식(CCleaner의 [Custom Clean 분석/결과](https://support.ccleaner.com/articles/en_US/Master_Article/custom-clean-s-analysis-and-results-function), [Wise Disk Cleaner 검사 결과](https://www.wisecleaner.com/help/wisediskcleaner/how-to-use/common-cleaner.html), [Ashampoo Drive Cleaner 선택/예외](https://support.ashampoo.com/hc/en-us/articles/18709519406354-WinOptimizer-27-Manual))을 참고했습니다. [Avast의 Full 정리](https://support.avast.com/en-en/article/139/)에는 Downloads·백업·휴지통이 포함될 수 있어 이 앱의 대상에서 제외했습니다. Microsoft [Disk Cleanup 안내](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cleanmgr)는 지난주 내 수정되지 않은 임시 파일을 설명합니다. 이 참고 자료는 제품의 안전성 보증을 뜻하지 않습니다.

상단 도구 모음은 드라이브·경로·폴더 선택·분석·검색창·검색 버튼을 같은 한 줄에 배치합니다. 검색 방식·대소문자 구분·용량 기준은 오른쪽 조절 아이콘 옵션에 있습니다. 진행 상황과 결과 수는 검색 결과 탭에서 확인합니다. `Ctrl+F`로 검색창 이동, `Enter`로 검색, `F5`로 분석, `Esc`로 취소할 수 있습니다. 표와 디스크 맵 사이 경계선을 드래그해 높이를 조절할 수 있습니다. 최대화는 현재 모니터의 작업 영역을 사용해 작업표시줄 아래로 하단 내용이 가려지지 않도록 처리합니다.

논리 크기는 파일 데이터 길이입니다. 폴더 스캔의 할당 크기는 클러스터 단위 추정치이며, 압축·희소 파일·하드 링크 때문에 Windows의 실제 사용 공간과 다를 수 있습니다. 이 방식은 하드 링크를 중복 집계할 수 있고 대체 데이터 스트림은 포함하지 않습니다. MFT 모드는 레코드당 한 경로를 선택해 하드 링크의 중복 집계를 피하고 데이터 스트림을 합산합니다. 진단 정보는 엔진 결과에 보존하며 화면에는 표시하지 않습니다.

디스크 맵은 확장자별 고정 색상으로 파일을 표시합니다. 파일 유형 표의 색상 표시는 지도와 같으며, 유형을 선택하면 해당 파일을 강조하고 **유형 강조 해제**로 전체 색상을 복원합니다. 같은 확장자는 다시 실행해도 같은 색상을 사용합니다. 색상 구분 방식은 [WizTree 공식 변경 내역](https://diskanalyzer.com/whats-new)의 확장자별 색상 연결 기능을 참고했습니다.

## 프로젝트 독립성

```text
DiskAtlas/
├─ DiskAtlas.sln
├─ DiskAtlas.App/         # WPF 화면, 공간 지도, 전용 아이콘
├─ DiskAtlas.Start/       # 최초 설치·업데이트·등록된 관리자 실행
├─ DiskAtlas.Start.Checks/ # 패키지·경로·작업 정의 검사
├─ DiskAtlas.Core/        # 디스크 스캐너, 파일 내용 검색, 중복 판별·삭제 검증
├─ DiskAtlas.Checks/      # 파일 데이터와 성능 검사
├─ DiskAtlas.UiChecks/    # WPF 화면·동작 검사
├─ DiskAtlas.OptimizationChecks/ # 저장소 최적화 정책·삭제 검사
├─ launcher.app.json     # 런처 등록 정보
└─ dist/win-x64/          # DiskAtlas.exe 실행 도우미 + app/ 실제 앱
```

`parapara`, `FolderCompareWPF`, `SwiftCopy`, 런처에 대한 소스·DLL·프로젝트 참조가 없습니다. 자체 솔루션에서 따로 개발할 수 있습니다. `parapara/diskcheck`는 시스템 검색 제외 정책과 기존 사용 흐름의 참고 자료로만 사용했습니다.

## 빌드

Windows와 .NET 10 SDK가 필요합니다.

Visual Studio에서는 `DiskAtlas.sln`을 열고 `DiskAtlas.App`을 시작 프로젝트로 실행합니다. `DiskAtlas.Core`는 앱 내부 엔진 라이브러리입니다.

```powershell
dotnet build .\DiskAtlas.sln -c Release -p:ILuncherIntegrated=false
# 앱의 dotnet run은 관리자 터미널에서 실행
dotnet run --project .\DiskAtlas.App -c Release -p:ILuncherIntegrated=false
dotnet run --project .\DiskAtlas.Checks -c Release
dotnet run --project .\DiskAtlas.Start.Checks -c Release
dotnet run --project .\DiskAtlas.Checks -c Release -- --benchmark
dotnet run --project .\DiskAtlas.UiChecks -c Release
dotnet run --project .\DiskAtlas.OptimizationChecks -c Release
dotnet run --project .\DiskAtlas.RecycleChecks -c Release

# DiskAtlas 변경을 포함한 통합 프로그램 게시
..\Build.ps1 -App disk-atlas
```

성능 검사는 임시 폴더에 파일 100,000개를 생성하므로 일반 검사와 분리되어 있습니다. 측정에서 파일 생성 시간은 제외하고 결과 개수와 총 바이트를 함께 검사합니다. 결과와 측정 환경은 `artifacts`에 기록합니다.

`DiskAtlas.RecycleChecks`는 직접 만든 임시 파일만 사용해 실제 Windows 휴지통 이동과 보관본 유지를 확인합니다. 휴지통으로 이동된 시험 파일은 내용 확인을 위해 남겨 두며 기존 휴지통 항목은 변경하지 않습니다. 중복 파일 기능의 최신 검증은 [중복 파일 검증 보고서](../artifacts/diskatlas-duplicates-verification.md)에 기록합니다.

## 관리자 실행 등록

기존 독립 배포본은 게시 폴더 최상위의 `DiskAtlas.exe` 실행 도우미를 사용합니다. `app/DiskAtlas.exe`는 실제 관리자 앱이므로 직접 열면 매번 UAC가 표시될 수 있습니다. 통합 런처는 이 도우미나 예약 작업을 사용하지 않고 자체 실행 파일을 승격합니다.

설치 위치는 `%ProgramFiles%\i-luncher\DiskAtlas\<계정 SID>\`이며, 작업 스케줄러에는 `\i-luncher\DiskAtlas-<계정 SID>`가 등록됩니다. 설치된 파일은 일반 사용자에게 읽기·실행만 허용하고, 작업은 이 보호된 앱만 실행합니다. 게시 파일의 SHA-256 목록을 검증한 뒤 설치하며, 새 버전은 별도 폴더에 둡니다. 관리자 그룹에 속한 현재 계정의 승격을 사용합니다.

```powershell
# 등록·업데이트만 수행하고 앱은 열지 않음
Start-Process .\dist\win-x64\DiskAtlas.exe -ArgumentList '--install' -Wait
# 현재 계정의 실행 작업과 보호된 설치 파일 제거 (관리자 승인 필요)
Start-Process .\dist\win-x64\DiskAtlas.exe -ArgumentList '--uninstall' -Wait
```

등록 해제해도 프로젝트의 소스와 게시 폴더는 유지됩니다. 작업 폴더가 네트워크 드라이브에 있어도 최초 설치 도우미는 로컬 임시 설치 폴더에서 실행됩니다.

실행 도우미 검사 47개가 통과했습니다. 패키지 변조·경로 이탈·중복 파일·작업 권한 변경을 거부하고, 일반 사용자 권한에서 설치 준비 폴더를 잠그고 정리하는 동작을 확인합니다. 게시된 패키지 402개 파일의 SHA-256도 검증했습니다. [게시 EXE 검사](artifacts/start-package-check.json)에는 실행 도우미의 `asInvoker`, 실제 앱의 `requireAdministrator`와 아이콘 확인 결과가 있습니다.

업데이트 때 이전 설치 버전은 보존됩니다. 제거 도중 다른 창에서 앱을 동시에 열면 일부 파일이 남을 수 있으므로 앱을 닫고 제거를 다시 실행하세요. 최초 승인하는 설치 도우미의 단일 파일 런타임 추출은 .NET 기본 정책을 사용하고, 반복 실행하는 관리자 앱은 보호된 폴더에서 DLL을 직접 로드합니다.

## 측정 결과

아래 표는 2026-09-14 초기 버전에서 이 PC의 일반 사용자 권한으로 측정한 값입니다. AND/OR 검색과 새 지도 적용 후의 검색 속도를 나타내는 수치는 아닙니다.

| 대상 | 작업 | 측정 시간 |
| --- | --- | --- |
| 실제 C: 드라이브, 파일 1,087,684개 | 병렬 폴더 스캔 | 19.286초 |
| 생성 직후 작은 파일 100,000개 | 병렬 폴더 스캔 | 0.086초 |
| 분석한 파일 100,000개 | 파일명 검색 | 0.229초 |
| 작은 텍스트 파일 10,000개 | 내용 검색 | 0.533초 |

C: 검사에는 기존 파일과 테스트 자료가 포함되며 접근할 수 없는 항목 176개를 건너뛰었습니다. MFT 원시 볼륨 접근은 현재 권한에서 거부되어 일반 스캔으로 전환됐습니다. **실제 관리자 MFT 스캔의 속도는 이 환경에서 검증하지 않았습니다.** 레코드 파싱, 손상 거부, 경로 복원과 용량 집계는 합성 MFT 레코드로 검사했습니다.

작은 파일 시험은 파일당 46바이트이고 생성 직후 캐시의 영향을 크게 받습니다. 일반 디스크 전체 스캔이나 큰 문서의 내용 검색에 이 수치를 그대로 적용할 수 없습니다. 측정 원문은 [benchmark.md](artifacts/benchmark.md)와 [drive-check.json](artifacts/drive-check.json)에 있습니다.

파일 데이터·검색·MFT 합성 레코드 검사 16개와 화면 검사 41개가 통과했습니다. 화면 검사에는 AND/OR와 이름+본문 조합, 잘못된 조건의 사전 거부, 시스템 파일 검색 제외, 색상 범례 강조, 실제 바이트 정렬, 취소 후 기존 결과 보존, 할당 크기 전환, 지도 생략 면적 비율과 희소 파일 처리, 10만 파일의 화면 반영이 포함됩니다. 새 지도 적용 후 10만 파일 분석·화면 반영은 1.329초였고 UI 타이머의 최대 지연은 745ms였습니다([ui-scale-check.json](artifacts/ui-scale-check.json)). 큰 결과를 처음 화면에 반영할 때는 잠깐 지연될 수 있으며, 이후 지도 위의 마우스 이동은 캐시된 그림과 선택 테두리를 사용합니다.

[960개 파일의 색상 지도 검사 화면](artifacts/DiskAtlas-dense-map.png)에서는 24개 폴더와 12개 파일 유형을 확인할 수 있습니다.

## 기술 참고

- [WizTree 공식 설명](https://diskanalyzer.com/about): NTFS MFT 직접 읽기를 사용하는 용량 분석 방식.
- [Microsoft: Master File Table](https://learn.microsoft.com/en-us/windows/win32/devnotes/master-file-table): 파일 레코드, 속성과 확장 레코드 구성.
- [Microsoft: FSCTL_GET_NTFS_VOLUME_DATA](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_ntfs_volume_data): NTFS 볼륨 메타데이터 조회.
- [Microsoft: FSCTL_GET_NTFS_FILE_RECORD](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_ntfs_file_record): MFT 파일 레코드 조회.

WizTree와의 속도 동등성을 보장하는 수치는 아닙니다. 저장 장치, 캐시, 접근 권한, 파일 개수와 스캔 방식에 따라 실제 시간이 달라집니다. 파일 검색은 파일 시스템의 실시간 스냅샷이 아니므로 분석 이후 파일이 변경되었으면 다시 분석하세요.
