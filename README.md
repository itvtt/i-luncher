# i-luncher

GitHub에 프로젝트별로 릴리스된 앱을 한곳에서 설치·업데이트·실행하는 런처입니다.

배포 · 운영 전체 정리(일반 · 마스터, 앱 목록, GitHub 업데이트, 저장소 공개, 설정 키, 처음 구성): [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)

- 앱은 **GitHub 저장소 주소**로 추가합니다. 런처가 그 저장소의 **최신 릴리스 태그를 버전으로** 보여 줍니다.
- **일반 화면(일반 사용자)은 홈 화면 하나**입니다 (맥 · 아이폰처럼): 왼쪽 메뉴 · 스토어 없이 가운데 큰 아이콘과 아래 독(즐겨찾기 · 실행 중 · **+**). 아이콘은 기본 앱(빌드 설정 `GENERAL_APPS`, 기본 DeskCal 하나)과 그 PC 에 이미 설치한 앱 · 내 앱 · 내 PC 프로그램이고, 누르면 바로 실행 (받지 않은 앱은 흐리게, 이름 아래 받기). 업데이트할 앱이 있으면 아이콘 위에 "업데이트 N개 · **모두 업데이트**". 위쪽 가운데에 색 아이콘이 든 **분류 필터**(전체 · 즐겨찾기 · 업데이트 · 분류마다, 개수).
- 마스터 화면은 앱스토어처럼 **왼쪽 메뉴**(검색 · 스토어 · 분류마다 · 설치됨 · 즐겨찾기 · 업데이트)와 오른쪽 내용입니다. **스토어**는 앱을 한 줄씩(아이콘 · 이름 · 분류와 버전 · 설명 · **받기/열기/업데이트** 단추, 줄을 누르면 **앱 페이지**: 상세 설명 · 스크린샷 · 새로운 기능), **설치됨**은 이 PC 에 설치한 앱 · 내 앱 · 내 PC 프로그램을 큰 아이콘으로(누르면 바로 실행). **설치된 버전보다 높은 릴리스가 있으면 업데이트한 뒤** 실행합니다. 버전은 제목 표시줄에만 보입니다.
- 스토어는 **기본 목록**(GitHub 공지 저장소, 모두에게)과 **서버 목록**(API 서버, 마스터 계정만)입니다: [일반 · 마스터 배포](#일반--마스터-배포).
- 앱마다 아이콘 밖 오른쪽 위에 작은 **버전**(설치된 버전, 받지 않은 앱은 최신 버전. 회색 판)이, 이름 아래에 **상태 단추**가 있습니다: **받기**(파랑, 설치 확인) · **업데이트**(파랑) · **실행 중**(초록, 누르면 앞으로) · **진행 중 42%**(받는 중). 설치됨 탭에는 **열기** 단추가 없습니다 (아이콘을 누르면 실행, 스토어 줄에는 있음).
- 트레이 아이콘을 두 번 누르면 큰 창이 열립니다 (한 번 누름에는 아무것도 뜨지 않음).
- 설치된 앱은 런처 없이 **따로 실행해도 스스로 업데이트**합니다 (각 앱의 자체 업데이터: [AppKit](AppKit/README.md), DeskCal·Terminal Notes는 자체 구현).
- 기본 목록은 GitHub 공지 저장소(`i-luncher-notices`)의 `basic-apps.json` + `basic-media/` (GitHub 에서 고치면 런처 릴리스 없이 반영, 이 저장소의 [`basic-apps.json`](basic-apps.json)은 런처에 든 예비 목록), 서버 목록은 **API 서버** i-api(이 저장소의 `CDEP\i-api.csproj`, 예: `http://<서버 IP>:2003`)가 관리합니다. 마스터 계정만 받고, 추가·수정·삭제는 서버 PC 의 **i-api 관리 창 → 앱 목록**에서 합니다. API 서버가 없으면 i-luncher 저장소의 [`catalog/apps.json`](catalog/apps.json)을 읽습니다 (GitHub에서 직접 고침).
- 릴리스(버전 확인 · 설치 · 업데이트)는 런처도 각 앱도 그 앱의 **GitHub 저장소에 바로** 묻습니다 (Actions 러너가 올린 릴리스, API 서버를 거치지 않음). 비공개 저장소는 **프로젝트마다 넣은 토큰**(앱 우클릭 → 토큰…, 앱의 자체 업데이터도 같이 씀), 마스터 PC 는 그 PC 의 git 로그인으로 읽습니다.
- i-luncher 자신도 이 저장소의 **Actions 러너가 릴리스**하고, 설치된 런처는 시작할 때 **스스로 업데이트**합니다.

github.com과 GitHub Enterprise Server(`https://<호스트>/api/v3`) 모두 같은 방식으로 동작합니다.

```text
GitHub
├─ team/i-luncher            ← 이 저장소: 런처 소스 + catalog/apps.json(앱 목록) + 공지.txt
│    └─ Releases: i-luncher-Setup.exe, i-luncher-win-x64.zip
├─ team/DeskCal              ← 앱마다 자기 저장소와 Actions 러너
│    └─ Releases: DeskCal-win-x64.zip (+ DeskCal-Setup.exe)
├─ team/FastCopy …
└─ team/EQStatus (Velopack)      ← 설치 프로그램 방식도 지원

사용자 PC (%LOCALAPPDATA%\Programs)
├─ i-luncher\                ← i-luncher-Setup.exe 로 설치, 스스로 업데이트
├─ DeskCal\                  ← 런처가 설치, 앱이 스스로도 업데이트
└─ FastCopy\ …
```

## 사용

1. 릴리스의 **i-luncher-Setup.exe**를 실행합니다. 관리자 권한 없이 `%LOCALAPPDATA%\Programs\i-luncher`에 설치되고 시작 메뉴·바탕화면 바로 가기가 생깁니다. PC에 .NET 10 Desktop Runtime이 없으면 설치 폴더에 함께 넣습니다.
2. 왼쪽 메뉴에서 **스토어**(또는 그 아래 분류) · **설치됨**을 고릅니다. 처음 열면 설치한 것이 있으면 설치됨, 없으면 스토어가 열립니다.
   - **스토어**: 앱 목록의 앱이 한 줄씩 놓입니다. 회색 줄에 분류와 버전(설치했으면 `설치됨 v1.1.4`), 그 아래 설명, 오른쪽에 단추. 줄을 누르면 **앱 페이지**(아이콘·이름·큰 버튼, 버전 · 최근 업데이트 · 최초 출시 · 분류 · 개발자 · 크기, 스크린샷, 상세 설명, 새로운 기능). 뒤로 · Esc · 마우스 뒤로 단추로 스토어.
   - **설치됨**: 설치한 앱 · 내 앱 · 내 PC 프로그램이 큰 아이콘으로 놓입니다. 아이콘 밖 오른쪽 위에 작은 버전, 아래에 상태 단추(받기 · 업데이트 · 실행 중 · 진행 중, **열기 단추는 없음**). 앱 페이지는 없습니다.
3. 설치됨의 아이콘이나 상태 단추, 스토어 줄 · 앱 페이지의 단추를 누르면:
   - **받기** (미설치) → 버전·파일·설치 위치를 보여 주고 설치 여부를 묻습니다. 설치 후 실행합니다.
   - **설치됨, 새 버전 있음** → 업데이트한 뒤 실행합니다. 앱이 실행 중이면 종료하고 업데이트할지 묻습니다 (아니면 지금 버전을 엶). 업데이트가 실패해도 이전 버전은 그대로 남아 실행됩니다.
   - **설치됨, 최신** → 바로 실행합니다. **이미 실행 중이면** 새로 열지 않고 그 창을 앞으로 가져옵니다 (최소화돼 있으면 되살림). 하나 더 열려면 **Ctrl+클릭**. 독 · 내 PC 프로그램도 같습니다. (최근 2분 안에 확인하지 않았으면 실행 전에 한 번 더 확인)
   - 단추에 마우스를 올리면 설치 위치·릴리스 날짜·확인 실패 이유가 나옵니다 (`확인 중…` · `확인 실패` · `릴리스 없음`은 글자로).
4. 설치됨의 아이콘에 마우스를 올리면 왼쪽 위에 별(즐겨찾기). 우클릭(스토어 줄도): 즐겨찾기 · 업데이트 · 설치/다시 설치 · 저장소 열기 · 릴리스 노트 · 설치 폴더 열기 · 제거 (내 앱은 **편집…** · **내 앱에서 삭제…**도).
5. 왼쪽 메뉴의 **즐겨찾기** · **업데이트**(새 버전이 있을 때)는 설치한 앱에서 거릅니다. 업데이트 화면의 **모두 업데이트**는 한꺼번에 업데이트합니다: 실행 중인 앱은 한 번만 묻고 닫았다가 업데이트 뒤 다시 실행합니다 (취소하면 그 앱만 건너뜀).
6. 왼쪽 위 검색창(`Ctrl+F` 또는 `Ctrl+K`)은 지금 화면(스토어 또는 설치됨)에서 찾습니다. `F5`는 새로고침입니다. 앱 · 런처의 새 버전은 **시작할 때와 새로고침 때만** 확인합니다 (30분마다는 목록 · 공지만).
7. 맨 아래 가운데 **독**: 즐겨찾기(등록한 순서, 12개까지) | 즐겨찾기가 아닌 실행 중인 앱, 끝의 **+** 는 프로그램 추가. 실행 중인 앱은 아이콘 아래 흰 점이 있습니다 (창이 보일 때 4초마다 확인).
8. 공지 · 새로고침 · 설정은 제목 표시줄 오른쪽에 있고, 설정에서는 위의 **‹ 뒤로** · Esc · 왼쪽 위 로고로 목록에 돌아옵니다.

창을 닫으면(X) 트레이로 숨고 계속 실행합니다(목록 · 공지 확인을 이어 감). 트레이 아이콘을:

- **두 번** 누르면 큰 창이 열립니다. 한 번 누름에는 아무것도 뜨지 않습니다. 런처를 다시 실행해도 큰 창이 열립니다.
- 오른쪽 클릭 → **종료**로 끝냅니다.

설치한 앱은 Windows **설정 → 앱**에도 나오며 거기서 제거할 수도 있습니다. 런처를 제거해도 런처로 설치한 앱은 남습니다.

**제거하면 시스템 파일은 지우고 데이터는 남깁니다** (2.2.6, `Launcher\Services\SystemLeftovers.cs`):

- 앱을 제거하면 설치 폴더와 함께 그 폴더를 가리키는 Windows 등록을 지웁니다: 시작 메뉴 · 바탕화면 · 시작 프로그램 폴더의 바로 가기, 시작 프로그램 등록(Run · StartupApproved), **트레이 아이콘 설정**(설정 → 작업 표시줄 → 기타 시스템 트레이 아이콘, 예전 아이콘 그림이 여기 남아 있었음)과 그 알림 등록, 프로그램 이름 캐시, "앱" 목록 기록, 그 앱이 시작 프로그램 폴더에 둔 자기 실행 스크립트(이름이 앱 실행 파일과 같은 .vbs · .cmd · .bat). 앱의 자체 제거 프로그램으로 지우는 앱도, 그 프로그램이 앱을 실제로 지웠으면 같게 정리합니다.
- 런처가 시작할 때 뒤에서: 예전 런처(2026-11-07 전)가 캐시 폴더 `%LOCALAPPDATA%\i-luncher` 에 남긴 시스템 파일(`Apps` 앱 실행 사본 · `Workspaces` 빌드 작업 폴더 · `Releases` 예전 런처 버전 · `Previews` · `VersionState` · `runtime` · `notices` · `*-Setup` · `store-group.txt` · `.managed-payload.lock`)과 그것을 가리키던 시작 메뉴 · 트레이 등록을 지우고, 런처가 설치하는 폴더의 실행 파일인데 이제 없는 트레이 아이콘 설정도 지웁니다. 실행 중인 프로그램이 있는 폴더는 다음 시작 때 다시 합니다. 정션 · 링크는 링크만 지우고 가리키는 곳은 건드리지 않습니다.
- 런처를 제거하면(`uninstall.exe`) 런처 폴더를 가리키는 등록, 위 예전 파일, 런처 캐시(받아 둔 목록 · 아이콘 · 스크린샷 · 받은 파일 · 업데이트 임시 파일)를 지웁니다.
- **남기는 것**: 설치 폴더 밖의 앱 데이터(앱 설정 · 메모 · 내보낸 파일, 예: `%LOCALAPPDATA%\<앱>Data`), 런처 데이터 `C:\i-luncher`(설정 · 토큰 · 즐겨찾기 · 내 앱), 캐시 폴더 안의 사용자 파일(`settings.json` · `favorites.json` · `usage.json` …)과 그 밖의 이름(예: 이 PC 의 Actions 러너 폴더), 다른 프로그램의 등록. 모두 HKCU 라 관리자 권한이 필요 없습니다.
- 앱을 설치 · 업데이트한 뒤에는 탐색기에 그 실행 파일 · 바로 가기의 아이콘을 다시 읽게 해 같은 경로의 예전 아이콘이 남지 않게 합니다.
- 설치된 앱의 트레이 아이콘 설정 그림은 Windows 가 처음 한 번만 찍어 두므로, 런처와 모든 앱이 시작할 때 자기 항목의 그림을 지금 아이콘으로 바꿉니다 (2.2.7, AppKit `AppTrayIcon`, `AppKit\README.md`).

### 즐겨찾기

**즐겨찾기**(버튼 줄의 즐겨찾기, 아래 독)에 런처 앱, 이 PC 의 일반 프로그램, **웹사이트**를 모아 두고 누르면 바로 실행합니다 (웹사이트는 기본 브라우저로 엶).

- 런처 앱: 아이콘에 마우스를 올리면 왼쪽에 나오는 별(☆/★) 또는 우클릭 → 즐겨찾기에 추가 / 빼기.
- 이 PC 프로그램 · 웹사이트는 **등록만 해서는 즐겨찾기가 아닙니다** (설치됨에만 보임). 즐겨찾기 · 독에 두려면 우클릭 → **즐겨찾기에 추가** (빼기도 같은 메뉴).
- 일반 프로그램: 독 끝의 **+** → **이 PC 프로그램…** → 설치된 프로그램(시작 메뉴) 목록에서 고르거나 찾아보기. 실행 파일·바로 가기·폴더를 창에 끌어 놓아도 추가됩니다. 우클릭: 실행 · 편집(이름·경로·아이콘·실행 인수) · 파일 위치 열기 · 삭제. 파일이 없어진 칸은 흐리게 보입니다.
- 일반 프로그램은 추가할 때 **분류**(지금 있는 분류를 눌러 고르거나 직접 씀)와 **설명**(아이콘 아래 "내 PC" 에 마우스를 올리면 보이는 한 줄, 비우면 경로)을 정합니다. 전체 앱과 분류 화면에서 그 분류의 앱 뒤에 함께 보입니다 (예: 릴리스 없이 exe 로 쓰는 Receive → 개발). 비우면 기타. 빼려면 우클릭 → 삭제.
- 웹사이트: 독 끝의 **+** → **웹사이트…** → 주소(`example.com` 처럼 짧게 써도 https)를 넣고 **확인**(Enter) → 그 사이트에서 이름과 아이콘을 가져옵니다. 브라우저의 주소 표시줄이나 링크를 창에 끌어 놓아도 주소를 넣은 채로 이 창이 열립니다. 우클릭: 열기 · 편집 · 삭제.
  - 아이콘은 페이지에 적힌 큰 아이콘(apple-touch-icon · icon, PNG · ICO)부터, 없으면 `/favicon.ico`. 작은 아이콘은 밝은 둥근 판에 얹습니다. 그 사이트에만 묻고 다른 아이콘 서비스는 쓰지 않습니다. 받은 아이콘은 `site-icons\` 에 두고, 못 받았으면 다음에 런처를 켤 때 한 번 더 받아 봅니다.
  - 아이콘이 없거나 사이트에 연결하지 못하면 알려 주고 아래 기본 아이콘을 펼칩니다. 주소는 그대로 저장할 수 있습니다.
- **아이콘 고르기** (프로그램 · 웹사이트 · 내 앱의 추가 · 편집 창): **자동**(프로그램 · 사이트 · 저장소 아이콘) / **기본 아이콘**(웹 · 홈 · 메일 · 대화 · 일정 · 문서 · 폴더 · 코드 · 도구 · 차트 · 음악 · 영상 · 사진 · 클라우드 · 쇼핑 · 사람 · 별 · 설정, 18가지) / **이미지 파일…**(PNG · JPG · ICO · BMP · GIF, 256px 이하 PNG 로 `custom-icons\` 에 복사해 둠, 원본은 옮기거나 지워도 됨).
- 이 PC 에만 저장합니다: `C:\i-luncher\favorites.json`.

### 설정

일반 사용자용입니다: **i-luncher 자동 업데이트** (누르면 바로 저장), **재설정** (목록 · 전체), **저장 위치** (`C:\i-luncher`, 열기). 재설정 · 저장 위치는 아래 "설정 · 저장 위치". 마스터에게는 위에 **API 서버**(주소: 서버 목록 · 앱 사용 기록이 가는 곳, 빌드 설정 `API_SERVER` 가 기본, [연결]하면 응답을 확인)와 **런처 공지 → GitHub에서 편집**이 더 있습니다. 비밀번호는 묻지 않습니다.
서버 목록 · Terminal Notes 공지 · API 같은 관리 일은 런처가 아니라 서버 PC 의 **i-api 관리 창**에서 합니다 (아래 "API 서버").

### 토큰

모든 저장소는 각 PC가 GitHub에 바로 묻습니다. 토큰이 없으면 공개 저장소만 됩니다 (IP당 시간당 60번). 비공개 저장소는 **프로젝트마다** 토큰을 받습니다: 앱을 우클릭 → **토큰…** (GitHub 프로젝트 추가 때는 읽지 못하면 그 자리에서 물음). 저장하기 전에 그 저장소를 그 토큰으로 읽어 보고, 이 PC 의 이 Windows 계정에만 암호화해 둡니다 (`settings.json` 의 `RepositoryTokens`). 런처와 **그 앱의 자체 업데이터**가 그 프로젝트의 토큰을 씁니다. 설정 화면에 토큰 하나를 넣는 칸은 없습니다. **마스터 PC 는 토큰을 넣지 않습니다**: 런처가 시작할 때 이 PC 의 git 로그인(저장소를 push 하는 그 계정, Git Credential Manager 등)을 창 없이 읽어 그 호스트 전체의 토큰으로 쓰고, 설치된 앱의 자체 업데이터도 같은 토큰을 씁니다. 프로젝트에 넣은 토큰이 있으면 그것이 먼저입니다. 모든 사용자에게 같은 토큰을 주려면 빌드 설정 `.env`의 `LAUNCHER_TOKEN`(읽기 전용, contents: read)을 런처에 넣으며, 런처 저장소와 같은 호스트에만 보냅니다.

## 내 앱 (GitHub 프로젝트 추가)

누구나 독 끝의 **+** → **GitHub 프로젝트…** 로 앱 목록에 없는 프로젝트를 이 PC 에 더할 수 있습니다 (`C:\i-luncher\my-apps.json`, 다른 PC · 사용자에게는 보이지 않음).

1. 저장소 주소(`https://github.com/소유자/저장소` 또는 `소유자/저장소`, 기본 호스트면 짧게)를 넣고 **확인**(Enter) → GitHub에 바로 최신 릴리스와 설치 파일(win-x64 zip 또는 설치 프로그램)을 확인합니다. 이름 · 설명은 저장소 값으로 채워 둡니다.
2. **이름 · 분류**(지금 있는 분류를 눌러 고르거나 직접 씀) · **설명**(한 줄) · **아이콘**(자동 = 저장소 아이콘, 기본 아이콘, 이미지 파일)을 정하고 **추가** → 설치됨 탭에 들어갑니다 (받기는 그 칸의 단추로). 설치 · 업데이트는 앱 목록의 앱과 같습니다.
3. 나중에 고치려면 우클릭 → **편집…** (저장소만 빼고 모두). 아이콘 그림은 `custom-icons\` 에 복사해 두고, 바꾸거나 내 앱을 삭제하면 그 복사본도 지웁니다. (예전에 넣은 스크린샷 그림 `my-media\` 도 내 앱을 삭제할 때 지웁니다)
4. 빼려면 우클릭 → **목록에서 삭제…** → 설치되어 있으면 **목록에서만 빼기**(설치된 앱은 그대로) / **설치된 앱도 제거**(설치 폴더를 지움, 폴더 밖 데이터 · 설정은 남음) 중에서 고릅니다.

- 릴리스나 설치 파일이 아직 없는 저장소도 더합니다: 미리 보기에 노랑 **릴리스 없음** · **설치 파일 없음**이 보이고, 홈 화면에는 **릴리스 없음**으로 있다가 릴리스가 올라오면 받을 수 있습니다. 이미 런처에 있는 저장소만 알려 주고 더하지 않습니다.
- 공개 저장소는 그대로 됩니다. 비공개 저장소는 [확인]했을 때 읽지 못하면 아래에 **이 프로젝트의 토큰** 칸이 나옵니다: 넣고 다시 확인하면 그 토큰으로 추가하고 저장합니다 (나중에 바꾸기는 우클릭 → 토큰…). 버전 정보도 그 저장소의 GitHub 릴리스에서 가져옵니다.
- 모두에게 보이게 하려면 공지 저장소의 기본 목록(`basic-apps.json`)에 넣습니다 (런처 릴리스 필요 없음). 마스터에게만 보이게 하려면 i-api 관리 창 → 앱 목록 (그러면 같은 저장소의 내 앱은 목록 것으로 보임).

## 앱 목록 관리 (추가 · 수정 · 삭제)

서버 PC 의 **i-api 관리 창** → **앱 목록**에서 합니다: [+]로 추가, 이름 · **분류**(직접 쓰거나 아래의 지금 있는 분류를 눌러 고름) · 저장소 · 설명 · id · 설치 폴더 이름 · 설치 방식 · 마스터만, [−]로 빼기, ↑↓로 순서. [저장]하면 런처가 목록을 바로 다시 읽습니다. 그 사이 다른 곳에서 목록이 바뀌었으면 저장하지 않고 다시 읽으라고 알립니다 (덮어쓰지 않음).
제작자 · 상세 설명 · 스크린샷은 스토어 줄을 누르면 열리는 앱 페이지에 보입니다 (스크린샷은 [+] 또는 Ctrl+V). 내 앱은 설치됨 탭에만 있어 앱 페이지가 없습니다.

서버 목록과 그 스크린샷은 **API 서버의 데이터 폴더**(`C:\ProgramData\i-api-data\launcher`)에 있고 저장소에는 없습니다. 그래서 소스를 다른 곳으로 옮겨도 앱 목록은 따라가지 않으며, 그곳 서버 PC 의 i-api 관리 창 → 앱 목록에서 따로 등록합니다.

받는 주소: `https://github.example.com/team/App`, `…/App.git`, `…/App/releases/tag/v1.0.0`, `git@github.example.com:team/App.git`, `team/App`(기본 호스트) 등.

`catalog/apps.json`은 GitHub에서 직접 고쳐도 됩니다. 필수는 `id`, `name`, `repository`이고 나머지는 비우면 자동입니다.

```json
{
  "schemaVersion": 1,
  "apps": [
    { "id": "deskcal", "name": "바탕화면 달력", "englishName": "Desktop Calendar", "repository": "https://github.example.com/team/DeskCal",
      "category": "일정", "description": "일정 · 4조 교대근무 표시", "installName": "DeskCal" },
    { "id": "eqstatus", "name": "EQ Status", "repository": "https://github.example.com/team/EQStatus",
      "kind": "setup", "installName": "EQStatus" }
  ]
}
```

| 필드 | 뜻 (비우면) |
|---|---|
| `name`, `englishName` | 이름 (무슨 앱인지 바로 알 수 있게), 영문 이름 (이름 옆에 작게. 비우면 안 보임) |
| `kind` | `zip`(릴리스 zip을 런처가 설치) 또는 `setup`(릴리스의 설치 프로그램 실행). 비우면 zip이 있으면 zip, Velopack 릴리스나 설치 프로그램만 있으면 setup |
| `asset` | 설치할 zip 이름, `*` 가능 (`win-x64`가 든 zip → 앱 이름으로 시작하는 zip → 하나뿐인 zip) |
| `setupAsset`, `setupArguments` | 설치 프로그램 이름과 인수 (`*Setup*.exe`/`.msi`, 인수 `/S`, Velopack은 `--silent`) |
| `installName` | 설치 폴더 `%LOCALAPPDATA%\Programs\<이름>`과 Windows "앱" 목록 키 이름 (`name`). **앱의 자체 업데이터·설치 프로그램과 같아야** 따로 실행해도 스스로 업데이트합니다. 앱 추가 창이 zip 이름(`DeskCal-win-x64.zip` → `DeskCal`)에서 채웁니다 |
| `formerInstallNames` | 이름을 바꾸기 전의 설치 폴더 이름 목록 (예: `["SwiftCopy"]`). 그 이름으로 깔린 앱도 설치된 것으로 보고, 다음 설치·업데이트 때 새 이름 폴더에 설치한 뒤 예전 폴더·"앱" 목록 기록·바로 가기를 지웁니다 (앱이 실행 중이면 다음 번에) |
| `formerIds` | 이름을 바꾸기 전의 id 목록 (예: `["swiftcopy"]`). 그 id 로 된 즐겨찾기를 이 앱으로 옮깁니다. 이 두 칸은 i-api 관리 창 → 앱 목록에서 id·설치 폴더 이름을 바꿔 저장하면 예전 값으로 자동으로 채워집니다 |
| `executable`, `arguments` | 실행 파일(설치 폴더 기준)과 인수 (설치 이름과 같은 exe → 하나뿐인 exe, `current\` 아래도 찾음) |
| `icon` | 카드 아이콘: 저장소 안 경로(`Assets/App.png`) 또는 https 주소 (아래 '아이콘') |
| `includePrerelease` | 프리릴리스도 최신으로 볼지 (false) |
| `order`, `category`, `description` | 표시 순서, 분류, 설명 |
| `details`, `screenshots`, `author` | 앱 페이지(스토어 줄을 누르면)의 긴 설명 (줄바꿈 `\n`), 스크린샷 (기본 목록은 공지 저장소 `basic-media/` 의 파일 이름, 서버 목록은 i-api 관리 창으로 올린 이름), 제작자 |

API 서버도 목록 저장소도 없는 빌드는 이 PC 목록 `C:\i-luncher\catalog.json`을 씁니다.

### 일반 · 마스터 배포

전체 정리: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)

런처도 설치 파일(`i-luncher-Setup.exe`, GitHub 릴리스)도 하나이고 기능 · 업데이트도 모두 같습니다. 누가 무엇을 보는지는 **이 PC 의 Windows 계정**으로 정합니다: 런처 빌드 설정 `MASTER_USERS` 에 있으면 마스터, 아니면 일반.

| 역할 | 누구 | 보이는 앱 | 공지 | API 서버 |
|---|---|---|---|---|
| 일반 | 마스터가 아닌 모든 사람 | **홈 화면**: `GENERAL_APPS`(기본 DeskCal) + 이 PC 에 설치한 앱 · 내 앱 (스토어 없음) | 있음 (GitHub) | **쓰지 않음** (로컬 앱) |
| 마스터 | 런처 빌드 설정 `MASTER_USERS` 의 계정 | 기본 목록 + **서버 목록** (i-api 관리 창에서 고치면 바로) | 있음 (GitHub) | 서버 목록 · 사용 기록 (설정 → API 서버) |

- **일반은 로컬 앱**입니다: 런처는 API 서버에 아무것도 묻지 않고, 런처 · 앱의 버전 확인 · 설치 · 업데이트는 그 앱의 GitHub 저장소(Actions 러너가 올린 릴리스)에서 바로 받습니다. 앱 사용 기록도 보내지 않습니다 (나중에 정함).
- 모두에게 나눠 주는 앱은 기본 목록으로만 관리하고, 그 밖의 앱은 각 사용자가 독의 **+ → GitHub 프로젝트…** 로 자기 PC 에 더해 씁니다 ([내 앱](#내-앱-github-프로젝트-추가)). 일반 사용자가 쓰는 저장소(런처 · 기본 목록 앱)는 토큰 없이 읽히게 공개로 둡니다.
- 사용자는 기본 목록 앱도 우클릭 → **목록에서 삭제…** 로 뺄 수 있습니다 (설치돼 있으면 목록에서만 빼기 / 설치된 앱도 제거). 뺀 앱은 `C:\i-luncher\removed-apps.json` 에 남아 **런처를 업데이트 · 다시 설치해도 다시 나오지 않고**, 사용자가 독의 **+ → 삭제한 앱 다시 추가**(또는 + → GitHub 프로젝트… 로 같은 저장소)로 다시 추가할 때만 보입니다. 기본 목록에 새로 넣은 앱은 그대로 보입니다.
- **기본 목록** = GitHub 공지 저장소(빌드 설정 `NOTICES_REPOSITORY`, 기본 `i-luncher-notices`)의 `basic-apps.json`(`BASIC_APPS_PATH`) + 스크린샷 `basic-media/`. 런처가 시작 · 새로고침 때 읽으므로 GitHub 에서 고쳐 `main` 에 저장하면 **런처 릴리스 없이** 반영됩니다. 읽은 목록은 이 PC 에 보관(`basic-apps-cache.json`)해 GitHub 에 닿지 못하면 그것을 쓰고, 형식이 틀리면 마지막 목록을 쓰며 마스터 화면에 오류를 띄웁니다. 그 저장소에 파일이 없거나 처음 실행이 오프라인이면 런처에 든 이 저장소의 [`basic-apps.json`](basic-apps.json) · `basic-media\`. `repository` 는 저장소 이름만 씁니다 (호스트 · 소유자는 빌드 설정 `LAUNCHER_REPOSITORY` 와 같게).
- 마스터 계정에는 제목 표시줄에 **일반 | 마스터** 전환이 있습니다. **일반**을 고르면 **새로 설치한 일반 사용자의 화면**이 됩니다 (홈 화면, 서버에 묻지 않음): 따로 둔 빈 데이터 `C:\i-luncher\general-preview` 를 쓰고 이 PC 에 설치된 다른 앱은 숨김. 일반으로 바꿀 때마다 그 폴더를 비우며, 일반 화면의 설정 → 재설정도 그 폴더만 지웁니다. 마스터의 즐겨찾기 · 내 앱 · 설정은 그대로. 고른 화면은 이 PC 에 기억합니다 (`settings.json` 의 `GeneralView`).
- 마스터를 더하고 빼려면 런처 빌드 설정 `MASTER_USERS` 를 고쳐 런처를 릴리스합니다 (설치 파일을 다시 나눠 주지 않음, 런처가 스스로 업데이트). 마스터의 런처가 서버에 닿지 않으면 마지막으로 받은 서버 목록을 보입니다.
- 부서 사람에게만 서버 목록을 보이는 역할은 아직 없습니다 (나중에 정함).
- 사용자가 지운 것은 런처 · 앱이 업데이트돼도 되살아나지 않습니다: 제거한 앱은 다시 설치되지 않고 (스토어에 받기로만 보임), 내 앱 · 즐겨찾기 · 설정 · 토큰은 `C:\i-luncher` 에 남아 업데이트가 건드리지 않습니다. 업데이트는 설치된 앱에만 적용됩니다. 처음으로 되돌리려면 설정 → **재설정** (아래 "설정 · 저장 위치").
- **서버 목록** = 서버 PC 의 i-api 관리 창 → 앱 목록. 기본 목록과 같은 앱(id · 예전 id)이면 서버 쪽 값이 보입니다.
- 예전 일반 · 부서용 설치 파일이 남긴 `%LOCALAPPDATA%\i-luncher\store-group.txt` 는 쓰지 않습니다 (설치 파일이 지움).
- 보이는 것만 나눕니다. 서버 목록 앱도 GitHub에서 받으므로, 받을 수 있는지는 그 저장소의 GitHub 권한(토큰)이 정합니다.

### 설정 · 저장 위치

백업해 새 PC 에서 다시 쓸 것만 **`C:\i-luncher`** 에 둡니다 (사용자 결정). PC 를 포맷하거나 바꿀 때 이 폴더만 백업했다가 같은 자리에 복사하면 됩니다.

| 폴더 | 파일 | 지우면 |
|---|---|---|
| `C:\i-luncher` (사용자 데이터) | `settings.json` (자동 업데이트, 일반/마스터 전환, 토큰) · `favorites.json` (즐겨찾기 · 내 PC 프로그램 · 웹사이트) · `my-apps.json` (내 앱) · `removed-apps.json` (목록에서 뺀 앱) · `custom-icons\` (고른 아이콘) · `my-media\` (내 앱 그림) | 되살릴 수 없음 |
| `%LOCALAPPDATA%\i-luncher` (캐시) | `basic-apps-cache.json` · `catalog-cache.json` (받아 둔 목록) · `notice-state.json` (읽은 공지) · `icons\` · `screenshots\` · `site-icons\` · `downloads\` | 다시 받음 |

- 즐겨찾기 · 내 앱은 고른 아이콘을 `C:\i-luncher\custom-icons\…` 전체 경로로 가리키므로 같은 자리에 복사해야 아이콘이 그대로 보입니다.
- **토큰은 옮겨지지 않습니다**: Windows 계정 · PC 마다 암호화(DPAPI)라 새 PC 에서는 풀리지 않고 무시됩니다. 비공개 프로젝트는 우클릭 → 토큰… 으로 다시 넣습니다 (마스터 PC 는 git 로그인을 자동으로 다시 씀).
- 예전 런처가 `%LOCALAPPDATA%\i-luncher` 에 둔 사용자 데이터는 새 런처가 처음 시작할 때 `C:\i-luncher` 로 옮깁니다 (아이콘 경로도 바꿈, `C:\i-luncher` 에 이미 있는 파일은 그대로). 캐시는 그 자리에 둡니다. `C:\i-luncher` 를 만들 수 없는 PC 는 둘 다 `%LOCALAPPDATA%\i-luncher`.
- 앱의 자체 업데이터(AppKit)는 런처 토큰을 `C:\i-luncher\settings.json` 에서 먼저, 없으면 예전 위치에서 찾습니다. 런처 자체 업데이트 임시 파일 · 못 보낸 사용 기록(`updates\` · `usage-pending.json`)은 AppKit 이 `%LOCALAPPDATA%\i-luncher` 에 둡니다 (캐시).
- 설정 → **재설정**: **목록** = `removed-apps.json` + 받아 둔 목록 (뺀 앱이 다시 보이고 목록을 새로 받음). **전체** = 위 표의 사용자 데이터와 캐시 모두. 누르면 그 줄 아래에서 한 번 더 확인하고, 런처를 다시 시작하며 지웁니다 (앞의 런처가 끝난 뒤, `i-luncher.exe --reset list|all --after <PID>`). 설치한 앱 · `catalog.json` · `공지.txt` · 그 밖의 파일은 지우지 않습니다.
- 설정 → 저장 위치 → **열기** 로 `C:\i-luncher` 를 엽니다. 한 PC 를 여러 Windows 계정이 쓰면 이 폴더를 함께 씁니다.

## API 서버

API 서버 `i-api.exe`(C#, `CDEP\i-api.csproj`, 3.0 부터. 2.23 까지는 Python `relay.py`)가 모든 API를 맡습니다 (서버 PC 한 대에서 돌림, C-DEP 에는 올리지 않음, [CDEP](CDEP/README.md)) (예전 Terminal Notes 중계 서버, 포트 2003 그대로). 설비 상태 DB(`EQUIPMENT_DB_*`)를 넣은 서버는 EQ Status 설비 상태를 **2004**(`EQUIPMENT_PORT`, 설비 상태만)에서도 내려 줍니다. 포트는 어디서나 API 2003 · 설비 상태 2004 입니다.

| 주소 | 쓰는 곳 |
|---|---|
| `/api/skills`, `/api/plugins`, `/api/announcements` | Terminal Notes (앱 키) |
| `/launcher/catalog` | i-luncher 마스터의 서버 목록 (저장은 관리자 비밀번호). 일반 사용자의 런처는 묻지 않음. `/launcher/notices` 는 남아 있지만 런처는 쓰지 않음 (공지는 GitHub) |
| `/launcher/usage` | 앱 사용 기록 (마스터 계정의 앱만 보냄) |
| `/api/v3/repos/<소유자>/<저장소>/…` | GitHub 중계: 예전에 빌드한 앱의 업데이트용으로만 남김. 지금 런처와 앱은 GitHub에 바로 묻습니다 |
| `/`, `/apps`, `/status` … | 관리 페이지 (관리자 비밀번호) |

API 서버 이름은 **i-api** 입니다. **런처에는 들어 있지 않고**(사용자 결정 2026-11-25: 런처의 관리자 메뉴는 없앰) 릴리스에 `i-api-win-x64.zip` 으로 따로 올라갑니다. 서버 PC 에서 마스터 스토어의 **i-api** 를 받아 열면 (서버 목록 앱, `selfUpdate`: 런처는 설치 · 실행만, 버전은 i-api 실행 파일의 것) **관리 창**이 뜹니다: 포트를 넣고 [실행] (설정 파일 · 로그인 자동 실행 · 방화벽 · 시작, 재부팅해도 다시 켜짐), 맨 위 ⋯ 에서 다시 시작 · 멈추기 · **업데이트**(같은 저장소의 최신 릴리스에서 새 zip 을 받아 바꿈, 설정 · 데이터는 그대로), 메뉴는 **API**(API 마다 켜고 끄기 · 호출 · 실패 · 걸린 시간) · 서버 앱 목록 · Terminal Notes 공지. 관리자 비밀번호는 그 옆 `settings.txt` 에서 알아서 읽습니다. 데이터는 `C:\ProgramData\i-api-data`에 따로 있고, 로그인 자동 시작은 시작 폴더의 `i-api.vbs` 입니다. 자세한 것은 [CDEP/package/README.md](CDEP/package/README.md) (zip 안의 README).
예전 Python 서버(`relay.py`)와 예전 이름(서버 `%LOCALAPPDATA%\TerminalNotesRelay`, 데이터 `C:\ProgramData\TerminalNotesRelayData`, `Terminal Notes Relay.vbs`)의 서버는 새 i-api.exe 를 처음 실행할 때 한 번 저절로 옮깁니다: 예전 서버를 멈추고, SETTINGS 를 옮기고, 자동 시작을 새 이름으로 바꾸고, 새 서버가 처음 시작할 때 데이터 폴더 이름을 바꾸고 러너 로그온 작업(`GitHub Runners`)도 새 서버를 가리키게 합니다. 방화벽 규칙은 예전 이름(`TerminalNotesRelay-2003`)도 그대로 인정합니다 (Windows 확인 창 없음). 예전 서버 폴더는 `MOVED-TO-i-api.txt` 와 함께 남깁니다.

런처는 빌드 설정 `API_SERVER`로 서버를 압니다 (마스터만 씀). 마스터는 **설정 → API 서버**에서 바로 바꿀 수 있습니다: `IP:포트` (포트는 서버에서 정한 것), 비우고 연결하면 빌드 설정의 주소. 바꾼 주소는 `C:\i-luncher\settings.json` 의 `ApiServer` 에 남고, 그 PC 의 서버 목록 · 스크린샷 · 설치된 앱의 사용 기록이 모두 그 주소로 갑니다 (런처를 다시 릴리스하지 않음). 앱의 업데이트는 서버를 거치지 않고 GitHub에 바로 묻습니다 (빌드할 때 `UPDATE_GITHUB_API=https://api.github.com` 또는 `https://<호스트>/api/v3`).

## 아이콘

앱 아이콘은 설치하기 전에도 앱 저장소에서 불러옵니다.

1. 카탈로그의 `icon`에 지정한 파일
2. 저장소 `.csproj`의 `<ApplicationIcon>` — 실행 파일 아이콘의 원본이라 가장 정확합니다. 테스트·설치 프로그램 프로젝트는 보지 않습니다.
3. 설치된 실행 파일의 아이콘
4. 저장소에서 이름으로 찾은 `.ico`/`.png` (Assets·Resources 아래, 이름에 icon·logo·앱 이름)
5. 아무것도 없으면 이름으로 정해지는 색 타일과 머리글자

받은 아이콘은 `%LOCALAPPDATA%\i-luncher\icons`에 두고 7일마다(못 찾았으면 하루마다) 다시 확인합니다. 저장소 파일 목록·프로젝트 파일·아이콘을 읽으므로 비공개 저장소는 읽기 토큰이 필요합니다.

글꼴은 앱에 넣은 Pretendard TrueType 판(SIL OFL 1.1, `Assets\Fonts\Pretendard-LICENSE.txt`)이고, 모든 창에서 글자를 **Ideal** 로 그립니다. Pretendard 에는 힌팅이 없어 화소에 맞춰 그리면(Display) 한글 획이 계단처럼 깨지고 굵기가 들쭉날쭉하므로 Display 로 되돌리지 않습니다 (EQ Status 와 같음). 화면은 휴대폰 홈 화면처럼 **큰 아이콘**입니다: 가운데 위 검색, 그 아래 버튼 줄(전체 · 즐겨찾기 · 업데이트(있을 때), 그리고 분류마다 색이 다른 아이콘과 개수, 고른 것은 흰 버튼), 그 아래 아이콘 칸이 분류로 나누지 않고 한 덩어리로 나옵니다(앱 목록 순서, 전체 앱과 분류 화면은 그 뒤에 내 PC 프로그램). 칸은 모두 같은 크기(폭 140, 창을 키우면 열만 늘어남)이고 한 줄이 안 차면 가운데에 모입니다. 칸 = 76px 아이콘(받지 않은 앱은 흐리게, 새 버전은 오른쪽 위 파란 ↑, 받을 수 있으면 오른쪽 아래 ↓, 내 PC 프로그램은 둥근 판 위 아이콘), 이름, 상태 한 줄. 마우스를 올리면 칸이 옅게 밝아지고 오른쪽 위에 즐겨찾기 별이 나옵니다. 진행 중에는 칸 아래에 진행 막대가 나옵니다. 맨 아래 가운데는 독입니다.

## 버전

- 앱의 최신 버전 = 그 저장소의 **최신 정식 릴리스 태그** (`v1.2.3`, `1.2.3.4`, `app-v1.2.3-beta.1` 모두 읽음). 비교는 숫자 순서, 같은 번호면 정식이 프리릴리스보다 높고, `+빌드정보`는 무시합니다.
- 설치된 버전 = 런처가 설치한 실행 파일이 그대로면 **설치한 릴리스 버전**, 앱이 스스로 업데이트해 실행 파일이 바뀌었으면 **실행 파일의 버전**, 그것도 없으면 Windows "앱" 목록의 `DisplayVersion`. 그래서 실행 파일 버전이 잘못 찍힌 앱도 같은 업데이트를 반복하지 않습니다 (툴팁에 차이를 보여 줌).
- 높은 릴리스가 있을 때만 업데이트합니다. 같거나 낮으면, 또는 버전을 알 수 없으면 업데이트하지 않습니다.
- 릴리스 워크플로는 **마지막 릴리스 + 1** (자리마다 0~9: `1.0.9` → `1.1.0`, `1.9.9` → `2.0.0`)을 고르고 `-p:Version`으로 넘깁니다. 프로젝트 파일의 `<Version>`은 바닥값이라 큰 변경은 거기를 올리면 됩니다 (예: `1.1.0`). 실행 파일 버전·태그·Windows 앱 목록 버전이 모두 같아집니다.
- 예전 i-luncher의 바이너리 지문 기반 앱 버전(`AppVersions.json`, 루트 `Directory.Build.targets`)은 없앴습니다. `Projects\` 아래 앱도 이제 자기 프로젝트의 버전 그대로 빌드됩니다.

## 배포 (GitHub)

### i-luncher 저장소

1. 이 폴더를 GitHub 저장소(비공개도 됨)로 올립니다. 앱들은 각자 저장소(`<소유자>/<앱>`)로 따로 관리합니다.
2. Windows x64 self-hosted 러너를 등록합니다 (레이블 `self-hosted`, `windows`, .NET 10 SDK 필요). 서버 PC에서는 i-api 설정 `RUNNERS_ROOT` 아래 저장소마다 한 폴더에 만들고 (GitHub 의 New self-hosted runner 안내, 서비스로 등록하지 않음), 로그온 작업 하나(`GitHub Runners`)가 켜 둔 러너를 시작합니다 ([CDEP/package/README.md](CDEP/package/README.md)).
3. 비공개·internal 저장소면 **Settings → Secrets → Actions**에 `ILUNCHER_ENV`를 만들고 [`.env.sample`](.env.sample)을 참고해 최소 `LAUNCHER_TOKEN=<읽기 전용 토큰>`을 넣습니다. 러너 PC에 `.env`를 두고 러너 환경 변수 `ILUNCHER_ENV_PATH`로 알려 줘도 됩니다. `LAUNCHER_REPOSITORY`는 비워 두면 그 저장소가 됩니다.
4. `main`에 푸시하면 [release.yml](.github/workflows/release.yml)이 확인(`Launcher.Checks`) → 빌드 → `vX.Y.Z` 릴리스(`i-luncher-Setup.exe`, `i-luncher-win-x64.zip`)를 만듭니다. 초안으로 파일을 모두 올린 뒤 공개하므로 파일이 빠진 릴리스가 최신으로 보이지 않습니다.
5. 모두에게 `i-luncher-Setup.exe` 를 한 번 나눠 주면 이후는 런처가 스스로 업데이트합니다 (설정에서 끌 수 있음). 서버 목록은 마스터 계정만 봅니다: [일반 · 마스터 배포](#일반--마스터-배포)

### 앱 저장소 규약

런처가 설치·업데이트할 수 있는 릴리스:

- 태그 `vX.Y.Z`, 파일 `<설치이름>-win-x64.zip` (실행 파일과 의존 파일이 든 폴더, 최상위 폴더 하나로 감싸도 됨). 설치 프로그램 방식이면 `*Setup*.exe`/`.msi`.
- 앱이 스스로 업데이트하려면: 설치 폴더 `%LOCALAPPDATA%\Programs\<설치이름>`과 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\<설치이름>`의 `InstallLocation`으로 "설치된 사본"을 알아보고, 같은 저장소의 최신 릴리스를 확인합니다. 런처는 설치할 때 이 키를 만들므로 런처로 설치한 앱도, 앱의 설치 프로그램으로 설치한 앱도 같은 방식으로 업데이트됩니다.

새 앱 저장소는 [AppKit](AppKit/README.md)을 넣으면 위 규약·자체 업데이트·Actions 릴리스가 한 번에 갖춰집니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File AppKit\Install-AppKit.ps1 -Project <앱 저장소>\MyApp\MyApp.csproj -RepositoryRoot <앱 저장소>
```

| 앱 | 릴리스 · 자체 업데이트 |
|---|---|
| DeskCal, Terminal Notes | 기존 자체 구현 (`build\Publish-Release.ps1`, `UpdateService.cs`) — 규약과 같음 |
| Compare, FastCopy, DiskScan | AppKit 적용 (`.github\workflows\release.yml`, `AppKit\`) |
| EQStatus | Velopack 자체 업데이트. 런처에서는 설치 프로그램 방식 (`kind: setup`) |
| file_shared | .NET Framework 4.8 + Windows 서비스라 AppKit 미적용. 릴리스 zip이 있으면 런처로 설치·실행은 가능 |

### 공지

**공지**는 모든 런처(일반 · 마스터)가 GitHub 공지 저장소(기본 `i-luncher-notices`, 공개)의 `공지.txt` 를 바로 읽습니다 (API 서버를 거치지 않음). 첫 줄은 제목, 다음 줄부터 본문, 공지 사이는 `---` 만 있는 줄. 고치기는 GitHub 에서 그 파일을 편집해 `main` 에 저장 (마스터의 설정 → 런처 공지 → **GitHub에서 편집** 이 그 페이지를 엶). 제목이 같으면 같은 공지이고 본문을 고치면 읽은 사람에게도 다시 알립니다. 읽지 않은 공지는 목록 위에 띠로 보입니다. 저장소는 빌드 설정 `NOTICES_REPOSITORY`, 파일은 `NOTICES_PATH`.

## 개발

```powershell
dotnet build i-luncher.sln -m:1
dotnet run --project Launcher.Checks          # 핵심 동작 확인 (가짜 GitHub·임시 폴더만 사용)
dotnet run --project Launcher                 # 개발 실행 (.env 없으면 이 PC 목록만, 자체 업데이트 없음)
powershell -NoProfile -ExecutionPolicy Bypass -File build\Publish-Release.ps1 -Version 1.0.0   # out\ 에 릴리스 파일
```

`ILUNCHER_DATA_DIR` 환경 변수로 설정·목록·캐시 폴더(기본 `C:\i-luncher` + 캐시 `%LOCALAPPDATA%\i-luncher`, 이 변수를 주면 둘 다 그 폴더)를 바꿔 시험할 수 있습니다. `Launcher.Checks -- --ui-snapshot <데이터 폴더> <png>`는 실제 창을 띄워 앱 상태를 출력하고 처음 화면 · 스토어(`-store`) · 설치됨(`-installed`) · 즐겨찾기 · 설정 화면을 PNG 로 저장합니다 (화면이 잠겨 있으면 그림은 빔). 스토어 줄을 누른 앱 페이지(`-detail`)도 그립니다. `MASTER_USERS` 에 없는 계정이면 기본 목록만 그립니다 (마스터 계정은 서버 목록까지). `ILUNCHER_SNAPSHOT_SITES=<주소,주소>` 를 주면 웹사이트 추가 창(사이트에서 이름 · 아이콘을 가져온 모습)도 그립니다. GitHub 프로젝트 추가 · 내 앱 편집 · 내 앱 삭제 창도 그립니다.

| 폴더 | 내용 |
|---|---|
| `Launcher\` | 런처 (WPF, .NET 10). `Services\GitHubClient`·`CatalogStore`·`AppInstaller`·`AppManager`·`ReleaseVersion` |
| `Launcher.Checks\` | 확인 프로그램 (NuGet 없음) |
| `installer\` | i-luncher-Setup.exe (.NET Framework 4.8, 런타임 동봉) |
| `AppKit\` | 앱용 자체 업데이터·빌드 설정·릴리스 템플릿 (런처도 같은 업데이터로 업데이트) |
| `build\` | 릴리스 스크립트 (버전 고르기, 빌드, GitHub Release 만들기) |
| `catalog\apps.json`, `공지.txt` | 런처가 API로 읽고 고치는 데이터 |

각 앱의 소스는 이 저장소가 아니라 앱마다 따로 있는 저장소(`DeskCal`, `TerminalNotes` …)에 있습니다. API 서버와 그 관리 창은 이 저장소의 `CDEP\` 에 있습니다 (i-api.exe, 런처와 따로 릴리스 파일).

예전 통합 빌드(앱 DLL을 런처에 포함), 소스 자동 검색·빌드, 온라인 시작 프로그램(Bootstrapper), 바이너리 지문 버전 체계는 GitHub 릴리스 방식으로 바뀌어 제거했습니다. 이전 파일은 git 기록에 있습니다.
